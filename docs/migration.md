# 跨环境配置迁移

“配置迁移”页面由 `src/pages/migrations.vue` 自动扫描接入。当前实现普通可移植归档、加密配置包、API 拉取及源端推送，均使用同一目标预检、修订保存及 Nginx 执行器。尚未运行构建、类型检查、测试、镜像构建或真实迁移，等待 P5 集中验收。

## 迁移内容

始终包含当前期望 Nginx 原生配置树，连同 HTTP/Stream、ACL、WAF 与相互引用。导入明确替换 Nginx 业务配置范围，不覆盖目标节点身份、管理员、API Key、管理入口、TLS 信任、主机 DNS、功能开关或 Agent 信任/救援记录。防火墙默认保留目标策略；可显式携带中立期望规则，按下述映射保存。内核运行规则、所有权及独立恢复记录始终保留在目标。

可显式选择证书与私钥、DNS 提供商凭据、ACME 账户及签发配置、通知渠道及其凭据、防火墙中立期望规则、监控设置和已保存的主机 DNS 配置。证书包括最新版本及当前配置引用版本；资源和证书版本在目标重新分配 ID，逻辑文件 ID 重新生成，证书引用按参数位置重绑定。业务配置树内部的站点/策略标识随同一树保留。秘密由源主密钥解密后放入 age 加密归档，目标再以自己的主密钥加密；不复制源密文或主密钥。

ACME 迁移须同时选择证书和 DNS 凭据，并先完成注册、签发及恢复。仅恢复现有注册记录，不发起新 CA 操作；同环境、相同账户密钥且 CA 地址一致的目标已注册账户可复用。签发配置自动续期/部署均关闭，HTTP-01 公网确认清除，订单与挑战租约不复制。通知渠道新增后始终停用，不复制旧投递队列或重放告警。

完整数据库的加密捕获、下载、离线检查及停机恢复材料准备已独立接入，见[完整备份](backups.md)。独立目标计划、隔离映射修订、固定数据库/运行请求核对、文件安装与受管 Nginx 应用已接入；补偿先确认原 Nginx 运行，再恢复目标原件。运行确认后可继续独立数据对账，终止旧流程并保存已生效修订；外部结果保留待核对。最终激活已接入独立数据库核对、不可回退批准及原维护会话释放确认，详见完整备份文档。已接入按次授权的原生组件准备和首次安装；主机 DNS 已接入下述显式映射与独立确认入口；普通可移植配置已接入下述受管字段重建与同一导入链路；完整首版的其他缺口继续按实施计划推进。

## 文件导出与导入

导出必须明确 `mode=portable|encrypted`，两种模式均要求 `backup.export` 及浏览器近期认证。默认可移植配置导出普通 `.tar`，口令为空、selection 全为 false；仅重建可识别的 HTTP/Stream 受管字段、IP 访问列表及基础 WAF。可映射的监听/域名、无凭据及路径的上游、数值/枚举设置、固定变量头及证书逻辑引用保留；自由原文、名称备注、任意头常量、URL/自定义路径、动态引用、全局调优、HTTP-01 与源模块路径省略。不可映射基本监听或上游的站点也省略，并报告数量。WAF 自定义路径和非标准方法不进入普通包。所有重建站点停用，检查并补齐原有保护后再明确启用。普通归档不证明外部来源可信。

`mode=encrypted` 保留完整原文及所选材料，额外要求 `backup.secrets/config.secrets` 和 16–256 字节口令，导出 `.tar.age`。包和口令需分别保管。未选择的可选文件不会写入归档；秘密目录只在选定对应材料时出现。

目标按内容识别格式，普通包不填口令，加密包输入原口令。普通包除固定清单和散列外，还须能从受管字段重新生成完全相同的规范化配置，并核对站点停用，不能仅靠 manifest 标志导入任意明文原生内容。两种包共用目标映射、依赖预检、修订和补偿执行器；目标导入权限仍覆盖替换现有原文与恢复材料所需的 `backup.restore/backup.secrets/config.write/config.secrets/security.write`。

预检仅接收当前 schema 6、固定 JSON 文件清单及 SHA-256，检测目标模块、原生指令、证书引用/有效性、资源容量、运行接入及未应用修订，并列出监听、域名和上游供核对。映射仅能替换识别出的指令参数；模块路径显式映射为空字符串时移除对应 `load_module` 指令，适用于目标已静态预置该能力的场景，其他参数不接受空映射。不执行包内脚本，不读取源机器绝对路径。缺失或未知镜像能力只能保留草稿；换用匹配镜像后重新预检，不能运行时增装模块。真实监听/目录/ABI 与配置检查沿用 Agent 的应用前检查及 `nginx -t`。

模块依赖沿 `nginx.conf` 的实际 include 上下文识别，分别检测 HTTP 与 Stream 的 map、访问控制、日志、连接限制及返回等能力；共享 include 按各自上下文检查，停用或未引用的文件不增加运行依赖。能力检测将映射表数据行作为数据处理，并检查受管发布探针及 HTTP-01 入口的附加模块需要。目标逐项列出源 `load_module` 路径是否存在对应批准内容；原生已批准但尚未加载的模块显示待验证，可继续应用前配置/ABI 校验与运行确认。缺少模块、路径未批准或镜像未预置能力时，计划明确阻塞，不能以当前运行的其他模块代替。预检最多展示 128 个明细，优先保留阻塞项，避免站点、监听及上游核对项挤占缺失依赖；超出时明确提示，全部项目仍参与准入判断。

计划有效期 30 分钟，执行支持 `draft`、`save`、`apply`；草稿不代表配置生效。保存和应用均要求精确基础版本，目标配置模块停用时须明确授权启用。导入需要 `backup.restore/backup.secrets/config.write/config.secrets/security.write`；恢复通知渠道另需 `notifications.write`，替换监控设置另需 `monitoring.write`，启用配置模块另需 `system.write`。

依赖资源、修订、任务、审计和幂等响应同事务保存。应用期间拦截其他 Nginx 修改/执行和模块开关。成功以原有 root 执行器确认运行结果为准；失败先核对原运行修订，再恢复原期望指针、本次迁入的安全策略、监控设置和本次启用的模块。配置头使用递增代次使旧客户端失效，不改写历史修订。不能证明运行恢复或遇到外部冲突时保留 `recovery_required`，不覆盖外部变化。导入的不可变修订、证书、凭据及停用的自动化配置保留，便于审计与重试；这些保留项不是已经启用的业务。

## 防火墙期望规则迁移

文件导出及 API 拉取/推送均可通过 `selection.firewall=true` 包含 `{source_backend, rules}`；未选择时归档项为 `null`。不复制源策略版本、模块开关、自动保护项、内核表达式、所有者标记或 root 恢复材料。当前仅接收 schema 6，不保留旧包兼容分支。

目标导入的可选 `firewall` 参数默认 `preserve`，保留目标期望及运行规则；显式 `merge` 合并、`replace` 替换目标期望策略。例如：

```json
{"mode":"merge","backend":"direct-nftables","interfaces":{"eth0":"ens3","eth1":""}}
```

每个源绑定接口都须明确映射，包括同名接口；空字符串明确解除绑定。缺少映射时任何执行模式均阻塞，不能借草稿隐式沿用源接口。目标后端须明确指定；合并有既有规则的目标时须保留其后端。可选 `base_version` 要求目标当前版本精确匹配；省略时准备阶段冻结当前版本，重新预检或重试不自动换用新版本。最多 256 项接口映射，规则在目标重新分配 ID，并保留源规则的同优先级执行顺序。合并时源、目标优先级不得重叠，须先显式调整冲突的顺序；不随机插入既有规则。总规则与内容仍受目标配额约束。

计划展示源规则、映射、既有规则保留/替换数量及目标版本；规则明细最多 64 条且不超过 64 KiB，超出明确标识。未观测到目标接口、模块停用或执行后端尚未适配会单独提示，保存期望不代表运行可用。仅在所有源接口映射明确且目标期望版本及内容未变时，才与 Nginx 修订、依赖及任务同事务保存；应用失败补偿也核对原迁入版本及完整内容，以新版本恢复旧期望。期间阻止新的防火墙期望修改与应用；原 root 操作的确认及恢复继续可用。冲突保留待恢复状态，不覆盖后续变更。

目标选择 firewalld 时，预检复用独立主机 policy 编译器，单独提示 Docker 路径、接口选择或展开规模的阻塞原因。可编译只表示可查看目标 rich rules；firewalld 写入及独立恢复仍未交付，迁入不会触发系统 policy 创建、reload 或永久配置修改。

`draft/save/apply` 都只保存防火墙期望，`apply` 仅应用 Nginx。迁移不启用防火墙模块、不调用内核写入、不继承源管理入口或 SSH 保护；生效须在目标按[防火墙独立流程](firewall.md)重新生成计划，核对本机保护项并由新 TCP/TLS 连接确认。

## API 一键迁入

在目标调用 `POST /api/v1/migrations/pull`，提供源节点 HTTPS API 和 Key；本地还需 `nodes.manage`。API 拉取和推送始终使用加密配置包，源 Key 需完整原文导出权限及来源网络授权。源节点可通过[受控管理监听](management-listener.md)、现有受保护网络、VPN 或管理员配置的代理提供 HTTPS API；迁移本身不改变管理入口或建立隧道。

```json
{
  "remote": {
    "url": "https://source.example.com:9443/api/v1",
    "api_key": "源节点导出 Key",
    "fingerprint": "",
    "node_id": "",
    "selection": {
      "certificates": true,
      "dns_credentials": true,
      "automation": true,
      "notifications": false,
      "firewall": true,
      "fail2ban": false,
      "monitoring": true,
      "host_dns": false
    }
  },
  "base_version": 0,
  "mappings": {"192.168.1.10:80": "0.0.0.0:80"},
  "mode": "apply",
  "enable_nginx": false,
  "firewall": {"mode": "preserve", "backend": "", "interfaces": {}},
  "monitoring": {"mode": "replace"}
}
```

`base_version` 从目标 `GET /nginx/config-tree` 取得；请求同时提供 `Idempotency-Key`。`mode=preview` 只拉取与预检，其余模式继续执行同一计划。响应统一为 `code/message/data/request_id/node_id`；`data.state=applying` 表示异步执行，继续读取 `GET /migrations/{id}`，直到 `succeeded/rolled_back/recovery_required`。

默认使用系统 CA；自签名证书须填写独立核对的叶证书 SHA-256。可用 `node_id` 固定预期源身份。连接禁止重定向和环境代理，目标解析及响应有界；不接受 link-local、组播、未指定地址或常见元数据地址。API Key 仅用于本次固定导出接口，不持久保存或写日志；源节点校验通过后，计划以源稳定 ID 绑定。此入口是专用一次性迁移，不提供任意 API 转发。

目标端拉取可额外提供 `dependencies`，沿用推送的按次授权组件准备与首次安装选项，例如：

```json
"dependencies": {
  "tag": "",
  "prerelease": false,
  "install": {"start": true, "enable": false}
}
```

该选项只用于 `draft/save/apply`，要求 `components.manage`；首次安装另需 `system.write`。请求受理后，`data.state` 可仍为 `planned`，通过同一 `GET /migrations/{id}` 的 `pull.state/stage/error/deadline` 跟随自动迁入，`dependencies` 返回原子任务关联。依赖准备、原生首次安装、维护释放及重新预检完成后，按原模式提交同一配置快照。选择 `start=false` 不保证满足应用条件；资产仅准备好也不代表已安装。目标已具备所需组件时直接继续原预检；Docker 缺少模块只能更换预置镜像。

迁入授权与原计划同事务保存，最多 30 分钟；源 API Key 和包口令不保存。包、映射、基础版本、执行模式及首次安装选项均固定，重试同一幂等键只读取原进度，不重新导出或续期。授权过期或目标版本变化停止新的配置提交，已接受的安装或应用继续核对原记录；任务缺失不自动重建。运行结果不明时保留恢复状态；终结后清除自动提交授权。完整备份恢复会清除源迁入授权，不在新环境续办旧操作。

其他入口：`POST /migrations/export`、`POST /migrations/plan`、`POST /migrations/{id}/execute`、`GET /migrations`。执行请求幂等；拉取请求在计划提交时持久关联幂等键，响应丢失后使用原请求和原键核对，避免重复迁入。

## 资源边界

加密包与解密归档各不超过 8 MiB，不使用压缩，不向磁盘解包。只接收固定十个普通文件（含 `config/host-dns.json`、`config/firewall.json`、`config/fail2ban.json` 和 `config/monitoring.json`），拒绝目录、链接、设备、重复名称、PAX、未知文件和非零尾随内容；全部 age 内容认证完成后才解析。scrypt 工作因子上限 18，每节点串行处理包。原文仍受 128 文件/2 MiB 配置树限制，证书材料合计 1 MiB；防火墙最多 1000 条、规范化策略最多 256 KiB；其他资源沿用各模块配额。

最多 8 个待执行计划、128 条保留记录及 128 MiB 迁移材料；状态摘要单独加密且不超过 256 KiB，列表不解密原始归档。预检展示最多 128 项，超限明确提示，所有项目仍参与准入判断。API 请求上限 12 MiB，远程响应与超时均有界；实际容量冲突会阻止事务提交。

迁移计划可通过 `POST /migrations/{id}/dependencies` 按次授权准备缺失的可信 Nginx 资产，输入 `tag` 和 `prerelease`，要求导入权限及 `components.manage`、浏览器近期认证和幂等键。目标仅使用本机已确认的发行信任；已有 Nginx 不替换，已有安装绑定需要恢复时不准备替代资产，Docker 缺少模块能力仍需换用匹配镜像。父任务授权最多 30 分钟且不超过原计划有效期；检查及准备子任务与父关联同事务提交，断连或重启不新建相同子任务。准备绑定检查过的资产、清单、信任及所需模块能力，缺少系统运行依赖或能力时停止；不安装系统包、不编译或增装 Nginx 模块。

## 源端推送式一键迁出

源节点调用 `POST /api/v1/migrations/push` 并提供 `Idempotency-Key`，或使用自动扫描的“迁出到节点”页面。输入格式沿用 `remote.url/api_key/fingerprint/node_id/selection`，但 remote 指向目标；另有 `mappings`、可选 `firewall`、`mode=preview|draft|save|apply`、`enable_nginx`、可选 `base_version` 和可选 `dependencies: {tag, prerelease, install?: {start, enable}}`。未提供基础版本时，首次受信连接读取并固定目标当前配置版本，后续不自动改用新版本。首次响应为 HTTP 202 的父任务；`GET /migrations/push` 列表及 `GET /migrations/push/{id}` 查询同一任务和目标逐项结果。preview/draft/save 的完成只表示对应步骤完成，apply 须等目标执行器确认生效才报告应用成功。

源端要求 backup.export、backup.secrets、config.secrets 和 nodes.manage，浏览器需近期认证。目标 Key 需 backup.restore、backup.secrets、config.write、config.secrets、security.write；迁入通知另需 notifications.write，替换监控设置另需 monitoring.write，启用配置模块另需 system.write，授权准备组件另需 components.manage，授权首次安装另需 system.write。目标通过 `GET /migrations/receiver` 提供当前版本和本 Key 权限，身份在首次连接后持久绑定；每个响应核对同一节点。目标接收使用 `PUT /migrations/receive/{id}`，固定 ID、配置包散列、Nginx/防火墙映射及基础版本的回执和计划同事务保存；重复 ID 的不同内容会被拒绝。执行沿用 `/migrations/{id}/execute` 和原幂等键，不另建导入执行器。

源端只导出一次并冻结包，在自己主密钥保护下暂存包、随机口令及本次目标授权；Key、口令和包正文不出现在任务响应、通用任务及审计中。授权一小时、单轮请求 35 秒、每次授权最多 128 轮，网络失败有限退避并遵守 Retry-After；串行 worker 在重启后先查询原目标计划。已确认计划缺失、身份变化、目标补偿不明或结果不符时停止新提交，不因超时判定目标停止。授权到期清除活动 Key：未提交者失败；可能已提交者保留加密恢复材料和待恢复状态。终态任务清除活动包及授权，保留加密摘要与审计；不宣称 SQLite 历史页已物理擦除。

预检未通过、权限不足或目标待恢复时可处理逐项结果，再调用 `POST /migrations/push/{id}/resume`，提供新的 `api_key` 和幂等键。此操作续授一小时，只继续原包、原节点、原模式和原阶段；更换目标 Key 后仍须有原计划所有者权限或 auth.manage，不绕过目标权限。映射、目标或基础版本需要改变时须创建新的迁移。依赖准备和原生首次安装沿目标关联父任务执行；完整快照仍使用独立完整备份流程，不由推送直接安装。Docker 所需模块仍必须来自预置镜像。

推送最多保留 64 条父任务，列表覆盖全部保留任务；推送暂存与导入计划共享 128 MiB，单条暂存最多 12 MiB、父任务摘要 264 KiB（目标结果及父任务元数据），目标响应最多 256 KiB。创建请求最多 2 MiB。未执行真实网络迁移、构建或测试，待 P5 集中验证。

目标 `Plan.dependencies` 展示父任务、检查/准备/维护/首次安装子任务及结果；GET 读取摘要，不解密整个迁移包。`install` 未提供时，`prepared` 只表示签名资产准备好。显式提供 `install: {start: true, enable: false}` 时，额外要求 system.write，且两个选项均须明确指定；仅支持已登记为未安装的原生目标，不接管已有实例。父任务自动进入维护、等待其他在途任务结束、提交原首次安装执行器、跟随同一安装结果、等待独立维护释放确认，然后用原包、映射、基础版本及资源 ID 重新预检。源端推送跟随同一父任务，再进入原配置执行器；文件导入仍由用户确认应用。`installed` 不表示迁移配置已应用；未启动、缺少依赖或存在配置冲突时，原预检继续阻塞。

环境修复后可在有效期内调用 `POST /migrations/{id}/preflight` 或页面“重新预检”，沿用原包、Nginx/防火墙映射、冻结的基础版本和资源 ID 更新预检结果；不会延长计划或替换配置。过期计划或基础版本变化需要重新创建预检。准备失败的父任务保留审计及子任务关联，重新准备需要新迁移计划，不能借恢复授权切换原准备选项。尚未执行构建、测试、真实下载或迁移，待 P5 集中验证。

新的原生目标节点可通过 [仅面板安装](../deploy/native/README.md) 的 `--without-nginx` 方式部署 Web/Agent，随后导入预检并按次授权准备及首次安装，或从源节点推送时设置上述选项。维护仅排除原子关联的协调父任务；其他任务和迁移仍须排空。同一目标一次只接收一个未结束的迁移依赖父任务。首次安装子任务和父关联同事务提交，安装授权不超过父授权期限且最多 10 分钟；断连或重启只核对原操作，不自动重建或续装。结果待恢复时保留维护，并通过“组件安装”页面/API 显式恢复或取消原任务。原任务终结后父任务继续核对并释放维护；授权到期停止新提交，已接收操作仍须核对真实结果。安装已完成但计划过期或目标版本变化时，不继续写入配置，需要新建迁移预检。Docker 仍使用预置模块镜像，不进入原生首次安装。自动协调尚未执行构建、测试、真实下载、安装或迁移，统一留待 P5。

## Fail2ban jail 期望配置

文件导出及 API 拉取/推送可选 `selection.fail2ban=true`，固定归档项 `config/fail2ban.json` 保存类型化 jail 期望；未选择时为 null。导入 `fail2ban: {mode: preserve|merge|replace, base_version?: number}` 默认保留目标，合并/替换与 Nginx 配置同事务保存，并支持失败补偿及目标版本冲突检测。源 jail ID 重新分配，站点逻辑 ID 随同一业务配置树保留；不复制实例、Socket、客户端批准、全局服务控制授权及加载单元摘要、所有权、计数或封禁状态。预检展示源/目标数量和状态；须在目标核对日志、白名单、流量路径及动作。本机受管实例提供 root 命令及独立网页/API jail 应用任务，迁移流程不自动应用或启动 jail；迁移保存不表示保护生效，详见 [Fail2ban](fail2ban.md)。

## 监控配置迁移

文件导出、API 拉取和推送均支持 `selection.monitoring=true`，固定归档项 `config/monitoring.json` 包含采样间隔、数据保留时间和 CPU/内存/磁盘阈值，未选择时为 null。当前仅接收 schema 6，不保留旧格式兼容分支。

目标参数 `monitoring: {mode: "preserve" | "replace", base_version?: number}` 默认保留目标。替换要求目标 `monitoring.write`；准备和执行分别检查当前权限。预检展示源设置及冻结的目标基础版本，重新预检不自动改用新版本。版本或内容变化须创建新计划。推送任务在传输前检查目标 Key 权限，并核对计划的模式、设置散列及版本，断连或重启后继续核对原计划。

`save/apply` 将监控设置与配置修订、其他依赖和任务同事务保存，提交后唤醒原监控 worker；沿用现有配置变更的采样与阈值窗口处理。`draft` 仅在计划中保留待迁入设置，显示“未导入”，不改变目标监控配置。目标监控模块开关、指标历史、告警状态与通知队列不随包复制。迁移应用中或待恢复时阻止另行修改监控设置；Nginx 应用失败先确认原运行配置，再按迁入版本与完整设置核对并以递增版本恢复原设置，冲突保留待恢复状态。未执行构建、类型检查、测试或真实迁移，待 P5 集中验证。

站点的 `client_deny` 元信息只迁移客户端拒绝入口声明；目标按本机 real_ip、map/volatile 和 geo 能力预检，并重新核对站点可信代理设置。独立的 `nginx/client-deny/sets.conf`、实际封禁、root 动作授权事件及集合恢复快照不进入配置包，导入和回滚沿用目标自身的运行集合。受管实例的 `jail-current.json`、`jail-bundles/`、`jail-configs/`、`jail-identities/`、封禁时间证明及 root 执行 journal 同样不迁移。目标 root 须对目标本机受管实例应用重新核对的 jail 策略，或明确授权已有实例的 jail 绑定，再由目标收集自己的实际封禁；导入入口不表示防护已生效，迁移保存后须在目标另行预览并确认 jail 应用。 宿主机动作的独立空表所有权、管理/代理来源批准事件和指针及 root 操作回执同样不迁移；可在目标本机重新登记空表并批准该目标的管理/代理来源，但这些准备不表示自动封禁已接通。


## 主机 DNS 配置迁移

文件导出、API 拉取及推送均支持 `selection.host_dns=true`。固定归档项 `config/host-dns.json` 只包含本应用已确认并保存的 DNS 期望配置，最多 64 个目标；不采集 DHCP 临时值、连接密钥或源主机系统文件，不复制源配置散列、接管授权或恢复快照。源节点未通过本应用确认的系统 DNS 不作为已保存设置导出；空列表会明确展示。

目标默认 `host_dns: {mode: "preserve"}`，保留当前运行 DNS。映射模式另需 `host.dns.write`，并为每个源目标提供显式映射，包括同名目标。

目标为本机明确接管的 netplan 时，预检按观测中的可写网卡或连接核对：networkd 继续使用 `networkd:<接口名>` 与平面配置，NetworkManager 使用 `UUID@接口名` 与地址族配置。跨类型须显式提供目标 config；导入不授予 netplan 所有者权限，也不执行源主机的系统命令。

例如普通文件映射为目标 NetworkManager 连接：

```json
{
  "host_dns": {
    "mode": "map",
    "mappings": {
      "": {
        "target": "12345678-1234-1234-1234-123456789abc@ens3",
        "config": {
          "servers": [],
          "search": [],
          "ipv4": {"servers": ["1.1.1.1"], "search": [], "automatic": false},
          "ipv6": null
        }
      }
    }
  }
}
```

空源/目标标识表示本应用接管的普通 resolv.conf，NetworkManager 标识为连接 UUID 与网卡的组合，networkd 标识为 `networkd:<接口>`。每个目标最多接收一个源配置。省略 `config` 时使用源逻辑配置；静态配置与双地址族配置之间转换、或源地址包含接口区域时，必须明确提供目标配置，不自动猜测地址族、自动获取或接口区域。

预检逐项显示源值、目标值及可生成计划的条件，检查当前 DNS 所有者、映射目标是否存在、写入支持、模块开关及未完成操作；读取失败明确报告。DNS 尚不具备写入条件时仍可保留迁移材料，其状态不代表已恢复 DNS，也不替代 Nginx 的预检结果。映射材料与原迁移计划一起加密保存；`draft/save/apply` 都不直接改写运行 DNS 或已确认期望值。`host_dns.state=staged` 只表示材料已保存，Nginx 应用或补偿不触发 DNS 变更。

在目标的迁移详情进入“在目标 DNS 页面配置”，加载映射后的配置，重新读取当前源版本，填写验证域名并明确确认接管，再沿用现有 DNS 计划、临时应用、确认和超时恢复流程。API 使用者从 `GET /migrations/{id}` 读取映射候选，结合 `GET /host/dns` 的当前目标与源散列，调用现有 `/host/dns/plan`、`/host/dns/apply` 及确认接口。源端推送详情只显示目标结果，不把目标配置加载到源节点的 DNS 编辑器。推送固定包内 DNS 散列、映射、目标及配置；重试和续授不能更换原材料。

当前归档只接收 schema 6，不兼容旧包；生成器、构建、类型检查、测试及真实迁移均未执行，统一留待 P5。

宿主机 Fail2ban 的官方 jail 来源批准事件及指针同独立登记、管理/代理保护批准一样，不进入逻辑配置包或完整备份恢复材料。导入不会授权目标内核封禁；目标须重新批准官方实例和 jail 来源，并核对完整当前集合。

宿主机 Fail2ban 一次性动作的运行检查点、不可变规则意图及独立 journal 同样留在源主机，不随配置包或完整备份恢复。导入不重放源主机样本、内核规则或所有权证明。

宿主机 Fail2ban 的持续会话批准、停止意图、父操作和当前子事务检查点不随逻辑配置包或完整备份迁移。导入不会自动建立持续执行权；目标机须独立核对登记、保护及官方实例/jail，并显式开启新会话，不能重放源主机封禁样本。

受管面板登录 jail 仍只迁移类型化逻辑策略，不携带来源的 managed 宿主机批准、保护前缀配置包、持续会话或所选 root jail 包。目标须建立本机授权并经统一 jail 预览与应用，导入不隐式开启内核执行。

宿主机失联动作范围的显式退役意图、原范围归档和完成证明同样留在本机，不随配置包或完整备份恢复；它们不能授权迁移目标重建规则。目标必须使用新的本机登记、保护/官方来源批准和持续会话。

同机重启恢复的 machine-id 摘要、显式恢复权限、恢复意图及派生授权链也不迁移。目标 API 导入不能继承源端 recover-on-boot；须由目标本机 root 重新批准当前会话，恢复封禁只采集目标官方实例的当前完整集合。


## 历史迁移材料

数据库历史维护沿用 `POST /history/preview` 与 `/history/execute`。`migration_keep=0` 不选择迁移材料；设置为 2–100 时，按每个操作者保留最新计划载荷，每批最多清理 100 个计划，截止时间按计划最后更新时间判断。除原历史维护权限外，还须有 `backup.restore/backup.secrets`；没有 `auth.manage` 时只处理自己的计划。计划摘要、接收回执、任务、执行结果和审计保留，计划列表与详情通过 `pruned_at` 标识材料清理时间。

只有已保存、执行结束或在截止时间前过期的计划可成为候选；应用、补偿、自动拉取授权、依赖准备及关联的检查/准备/安装/维护尚未结束，或关联记录缺失时不清理。执行在同一事务内重查预览摘要，清空计划原文、秘密及补偿载荷和已结束的依赖准备载荷；过期的未执行计划标记失败。材料清理后读取原载荷返回 `410 HISTORY_PRUNED`，不再创建新的执行或依赖授权；原执行身份、幂等键和选项可核对同事务保存的原执行结果，接收端仍识别原迁移 ID，不重建已清理计划。重新迁移须创建新计划。

128 条迁移计划上限按尚未清理载荷的计划计数，暂存字节配额仍按实际保留载荷计算。清理不删除历史摘要、不擦除旧备份或 SQLite 历史页，也不保证数据库文件缩小；源端推送父任务继续遵守原有 64 条保留限制。完整灾备准备清除源执行幂等回执并独立验证，新环境不继承该回执。当前数据库为 32，迁移归档仍为 schema 6，Agent 为 69；首版前不保留旧格式兼容。实现尚待 P5 集中验证。
