# 节点连接管理

本阶段接入手工 Token 登记、永久身份与能力核对、有限批量状态查看、受控业务资源转发、全局操作节点切换，以及删除连接时的授权撤销。目标节点仍是配置、任务和 Agent 的执行权威；控制节点只保存连接、加密 Token 与短期能力快照。尚未接入受控远程监听和一次性配对，当前仍需要管理员配置 HTTPS 入口。

现有逻辑配置迁移包不导出节点连接或远程 Token，目标已有连接保留。

## 接入方式

1. 在目标节点“设置 → 机器凭据”创建仅供该控制节点使用的 Token，至少授予 `read`，设置到期时间与允许来源。
2. 准备控制节点可达的受保护 HTTPS 入口，通过独立渠道核对入口证书 DER 的 SHA-256 指纹。
3. 在控制节点“节点连接”填写名称、HTTPS 根地址或 `/api/v1`、Token 和 64 位十六进制指纹。控制节点核对目标永久节点编号、凭据编号、授权范围、API/数据库/Agent/解析与策略版本，并读取目标能力后才保存连接。
4. 可选择最多 8 个节点检查状态，每个节点单独报告结果。列表读取使用已保存的检查时间，不自动向离线节点排队发送命令。

当前 `serve` 仍只绑定回环地址。此接入方式需要管理员已配置的 HTTPS 网关或受保护网络入口，不能直接把监听参数改成任意地址。应用按实际直连对端地址检查 Token 的来源，不信任 `X-Forwarded-For`；经网关时，目标凭据的来源匹配网关地址，外部来源限制由网关执行。控制节点核对的是 HTTPS 入口证书指纹。

Token 只在输入时经过浏览器，保存后使用本机 Vault 加密并绑定连接编号；列表、详情、检查和删除响应均不返回 Token。连接名称仅用于显示，不作为身份。首次登记拒绝当前节点或已登记的目标永久身份，后续检查不自动接纳身份或授权编号变化。

## API 合同

普通 JSON 统一使用 `code/message/data/request_id/node_id`。以下连接管理响应的外层 `node_id` 是控制节点编号；`data.node_id` 是目标永久编号，`data.id` 是本机连接记录编号。

| 路径 | 用途 |
| --- | --- |
| `GET /api/v1/nodes` | 连接及已删除记录 |
| `POST /api/v1/nodes` | 核对并登记连接 |
| `GET /api/v1/nodes/{id}` | 读取连接状态 |
| `POST /api/v1/nodes/{id}/refresh` | 检查已登记节点 |
| `DELETE /api/v1/nodes/{id}` | 删除并尝试撤销目标授权 |
| `GET /api/v1/remote/identity` | 目标报告当前机器 Token 的身份、授权及版本 |
| `DELETE /api/v1/remote/authorization` | 目标仅撤销当前机器 Token |

控制端需要 `nodes.manage` 与 `read`；登记、删除需要近期密码认证或有效机器 Token。连接管理写请求携带幂等键，浏览器同时校验 CSRF。登记和删除将幂等键与发起人、操作、输入散列、原连接绑定，不允许同键用于不同操作。检查可重复执行，不创建远程业务任务。

目标身份与自撤销接口仅接受机器 Token；自撤销无需 `auth.manage`，不能操作其他凭据。撤销请求必须携带 `X-Nginxpanel-Target-Node`，目标先核对永久节点编号再修改授权，避免把节点身份变化后的请求提交给另一节点。控制节点还检查响应外壳和返回凭据编号，只有明确收到匹配的撤销回执才报告成功。

节点访问复用迁移使用的 HTTPS 边界：固定 API 源、核对证书指纹和有效期、每次连接检查 DNS 解析地址、禁止重定向及环境代理。连接检查和撤销使用固定身份、能力及当前授权接口；业务资源转发使用独立 OpenAPI 白名单，不接收客户端临时地址或转发 Authorization。带 `X-Nginxpanel-Remote-Hop` 的请求不能再次调用节点管理，防止递归转发。

## 远程资源与前端节点切换

`api/remote.openapi.json` 是运行时嵌入的显式资源白名单，路径为 `/api/v1/nodes/{connection}/…`，复用主合同的请求/响应模型。配置、证书、ACME、日志、指标、通知、主机 DNS、组件、维护、更新及迁移操作在目标节点执行；账户、会话、机器凭据及连接管理保留在控制节点。没有通配转发入口，未登记的方法、路径和查询参数直接拒绝。

控制节点先检查 `nodes.manage/read` 及合同声明权限，再使用保存的 HTTPS 地址、证书指纹和 Token 发起请求。目标按自身 Token 授权与控制端实际用户权限的交集执行业务权限检查，敏感操作同时检查控制端近期认证。远程授权协议为 1，每次转发固定永久目标身份；写请求还先核对原凭据、身份及协议。目标在业务处理之前核对目标编号，响应的协议头、节点头、JSON 外壳及 SSE 数据再次核验。

JSON 响应保持目标的 `code/message/data/request_id/node_id` 和 HTTP 状态；控制节点产生的错误使用本机身份。日志下载保留受限 NDJSON，实时跟随逐帧校验，控制端会话或权限失效、近期认证过期时停止流。连接、Cookie、授权头及任意响应头不透传，SSE 不自动重新建立连接。

前端页级 API 固定操作节点、请求代次及取消信号。切换需确认丢弃表单，旧页面、对话框、请求和日志流一并关闭；旧异步回调不能向新节点提交请求。页面显示当前名称与永久编号，错误不自动回退到本机。账户和连接页明确显示本机管理；功能模块使用独立自动扫描页面，跟随操作节点。目标 401 不退出控制端会话，需重新检查连接。

普通转发最多并发 8 个，SSE 最多 4 个；普通请求最多 30 秒，SSE 最多 10 分钟，单次响应及 SSE 帧最多 32 MiB，流写入期限为 10 秒。目标只接收白名单中的查询参数；单请求体按资源限制为 4 MiB 或迁移的 12 MiB。幂等键按控制节点与发起人固定派生后转发；发送前、收到回执及未知结果均记录审计。断连和超时不自动重发业务命令，写操作结果未知时须查询目标原任务，重试沿用原幂等键。

## 状态、删除与中断

连接检查分别报告正常、不可达、身份变化、授权不可用和版本不兼容。正常检查结果超过 5 分钟时返回 `stale` 并隐藏过期能力；已到期授权返回授权不可用。缓存不会成为另一份配置权威，状态检查失败也不表示目标业务操作失败。

删除先持久记录 `removing` 与操作意图，再尝试撤销目标 Token。成功返回 `removed/revoked`；断连、超时、目标拒绝或无法核对回执时返回 `removed/pending`，清除本机 Token 和能力快照，同时保留目标永久编号及凭据编号，供管理员在目标节点补做撤销。已经删除的连接不会自动重新连接或重试远程操作。

进程在删除中断时保留原连接与加密 Token，页面可显式“继续删除”。重试仍只处理原连接的当前授权；若原请求已撤销 Token 但回执丢失，后续认证失败仍按待核对报告，不推断为撤销成功。目标自撤销与其审计同事务，控制端登记、检查和删除也保留发起人与请求审计。

活动连接最多 32 个，含已删除记录共 128 个；幂等操作记录最多 1024 条，达到上限明确拒绝新增。每次网络检查最多 15 秒，同时最多 4 个连接操作，同一连接不并发检查或删除。浏览器批量检查并发为 2，逐节点显示结果。删除结果在浏览器断开后仍使用最多 5 秒保存本机收尾。

数据库迁移为 20；本阶段未运行生成器、服务、网络检查、构建、类型检查、lint、浏览器或测试，待 P5 集中验证。
