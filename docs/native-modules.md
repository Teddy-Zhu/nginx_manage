# 受信 Nginx 动态模块

模块选择保存在配置树的主配置 `load_module` 中。Web 和 Agent 均只接受本机管理员批准的精确路径，不接受上传动态库、任意系统路径或脚本模块。Nginx 的该指令仅适用于主上下文；`--with-stream=dynamic` 表示动态构建方式，不代表已加载。参见 [指令说明](https://nginx.org/en/docs/ngx_core_module.html#load_module) 和 [构建选项](https://nginx.org/en/docs/configure.html)。

在主机上安装来源可信、匹配目标 Nginx 的模块，取得模块文件及 Nginx 二进制的真实 SHA-256。本阶段不自动安装系统包或下载模块；组件签名、来源和依赖核验由 P4 安装流程接入。

批准清单格式如下，散列须替换为实际值，此示例不能直接启用：

```json
{
  "version": 1,
  "modules": [
    {
      "id": "stream",
      "name": "Stream",
      "source": "/usr/lib/nginx/modules/ngx_stream_module.so",
      "sha256": "<模块文件的实际 SHA-256>",
      "binary_sha256": "<目标 Nginx 二进制的实际 SHA-256>"
    }
  ]
}
```

清单应置于 root 持有且普通账户不可写的目录，例如 `/etc/nginxpanel/native-modules.json`；Web 账户须可读取。清单、模块源文件及各级父目录均不能是符号链接，不允许组或其他账户写入；文件须为 root 持有的普通单链接文件。系统包中的符号链接需登记其实际规范路径。清单最多 16 项，同一 ID 可批准不同散列版本，精确路径不能重复；清单顺序也是界面保存时的加载顺序。

`serve`、`agent`、`nginx-init` 使用同一 `--nginx-modules=/etc/nginxpanel/native-modules.json` 启动参数；它不是业务数据，不由接口写入。未配置时不批准任何动态模块。修改清单后须更新相关进程的启动配置并重启；保留仍被运行修订引用的旧路径批准，新增未使用批准项不会改变旧发布的原文身份。

在“Nginx 配置 → 受信模块”选择版本并保存，再按正常流程应用。原文使用 `modules/<id>/<sha256>.so`，仅允许在主配置顶层、所有配置块之前加载。选择接口只定点修改模块指令；带参数注释或复杂位置的指令须先通过原文整理。移除模块前需清理依赖它的配置。

Agent 在持久操作记录之后准备 root 持有的不可变模块副本，检查批准散列、目标二进制绑定与原生 ELF 模块标识。已有副本只复用相同内容，不覆盖；随后真实 `nginx -t` 校验模块加载、版本、ABI 和整份候选配置。校验失败不切换运行配置。只有发布探针、监听及必要 TLS 核对通过后，才报告所选动态能力已运行。界面的“可选择”只代表批准内容和文件检查通过，不等于 ABI 已验收或已经加载。

发布清单保留模块散列、大小、二进制绑定及识别出的 Stream/Stream TLS/realip/SSL preread 能力。普通应用、回滚、外部检查和恢复均核对模块依赖；发送 HUP 前再核对当前发布。外部模块或二进制变化会暂停普通应用。损坏模块副本可由本机管理员修复，或批准新版本、重新选择并保存，再按完整冲突快照恢复；接口不会覆盖既有版本。二进制更新还需要本机专用实例维护或 P4 组件升级流程，配置恢复不会替换或重启 master。撤销批准不卸载正在运行的模块，后续配置须移除该选择；不在清单中的运行版本仍显示为已运行、不可选择。

资源上限：清单 64 KiB、16 项；单模块 8 MiB，单候选模块合计 32 MiB，二进制散列读取最多 64 MiB；源文件检查每次最多 16 份。模块存储最多 128 文件、256 MiB，保留依赖及中断暂存也计入；达到上限需本机维护，不自动删除仍可能用于恢复的版本。原生库依赖沿用本机受信系统环境，P4 组件交付还需记录依赖与许可证。

本阶段只完成实现与代码审阅，尚未执行构建、类型检查、模块加载或宿主机运行验证；真实 ABI、服务重启和故障恢复矩阵留到 P5 集中验证。
