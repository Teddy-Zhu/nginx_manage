# 实施计划与当前进度

依据 `Linux_Nginx_Manager_Design.md` 1.2 实施，完整首版范围保持 P0–P5。

首版正式发布前不维护旧接口、旧数据或旧需求的兼容分支；有变更直接更新当前合同。前后端 JSON 统一使用 `code/message/data/request_id/node_id`，HTTP 状态码保持原有语义。

页面路由由 `vue-router/vite` 自动扫描 `src/pages` 生成，菜单从页面元信息派生，禁止手工维护业务路由数组。阶段性完成后允许本地 commit，不自动推送。

| 阶段 | 可验收成果 | 当前状态 |
| --- | --- | --- |
| P0 | 开发入口、认证与权限、配置树/投影同事务修订、保真定点编辑、受限 Agent、能力与恢复合同、锁定依赖 | 基础代码已接入并审阅，待统一验证 |
| P1 | HTTP/HTTPS、Stream、ACL/WAF、Nginx 安全应用回滚、ACME 签发续期与证书部署 | 实施中：发布/确认/回滚及任务接入已实现，待统一验证；其余能力继续实施 |
| P2 | DNS 所有者适配与恢复、指标、各防火墙后端、Fail2ban、日志轮转查询、通知 | 未开始 |
| P3 | 远程授权与节点管理、迁移补偿、加密备份恢复 | 未开始 |
| P4 | 签名发布与更新、可信组件、systemd 安装、持久 Docker 运行 | 未开始 |
| P5 | 集中验证、真实系统能力矩阵、故障恢复与正式发布材料 | 未开始 |

依赖：P1 的所有配置变更进入 P0 的统一配置树服务；P2 的可达性变更使用 Agent 独立恢复记录；P3/P4 复用维护准入和幂等任务。不得将某个阶段标记为首版完成。

验证统一放在实现和集成稳定后。开发期间只阅读与审阅代码；不为阶段拆分提前运行构建、类型检查或回归，不创建 UI 自动化用例。真实系统验证需要独立 VM、测试域名及 ACME/DNS 授权、通知接收端；发布需要真实仓库与签名材料。

当前边界：原生树与常用字段共同保存修订，可新建基础 HTTP/Stream 配置。P1 已接入真实 `nginx -t`、不可变候选与原子指针、专用实例 HUP、修订探针/监听归属/TLS 指纹确认、失败补偿及 Agent 重启恢复；任务与前端已接通，只有运行确认后才更新已生效修订。已接受但记录缺失的操作停止重复执行；不确定的 IPC 提交继续使用原标识核对。

生产执行须由 root 在本机指定可信 Nginx 二进制及独立 worker 账户，先通过 `nginx-init` 创建无站点基线，再由专用服务使用固定 prefix/config 启动。开发 Agent 保持只读。安装器、账户/目录权限分区和 systemd/Docker 注册仍在 P4 实施；未在当前宿主机执行任何初始化、服务启动或配置应用。

P1 待补：完整代理 CRUD/字段、动态模块实际能力与接入、外部修改差异与处理入口、访问列表/WAF、证书导入和 ACME 生命周期。Go/前端构建、类型检查、lint 和业务测试均尚未执行，不将生成代码成功视为验证通过。
