# 工程合同

配置修订通过一个服务写入：原文、SHA-256、资源绑定与结构化投影同事务保存；原文及投影使用节点主密钥 AES-256-GCM 加密，附加数据绑定修订与逻辑资源 ID。完整原文接口要求 `config.secrets`，写入同时要求 `config.write`；浏览器读取/编辑原文须在五分钟内重新认证。安全指令还要求 `security.write`。

Crossplane 0.4.89 负责配置树语法分析，独立源码区间负责定点修改。稳定资源通过块前的 `# nginxpanel:resource <UUID>` 关联，不按域名猜测；同块的 JSON 元信息注释保存名称、备注与启停状态。include 文件继承实际调用位置的上下文，多处接入的资源文件拒绝歧义映射。未标记块保留原生可编辑状态，不自动认领；未登记指令可保存在独立草稿，但不能成为有效期望状态。

表单映射覆盖多条监听、域名、唯一直接转发 location 的前缀/上游/请求头/超时/缓冲/缓存/上游 TLS，以及证书路径、响应头、真实 IP、日志与 Stream 会话参数。字段以 `value/tokens/lines` 区分单值、同条指令参数和有序多条指令；新增、替换与移除只修改对应原文区间。请求/响应头仅映射已知变量；重复单值指令、参数注释、复杂 location、共享 include 等使相关字段只读。上游成员仅可编辑唯一接入、单一字面引用且没有 include 的组；变量引用或共享组保持原生编辑。

创建支持可选加权上游组。复制默认停用；可可靠映射的私有上游组同时复制，已知按资源分区的日志路径使用新 ID，其他原文保留。删除不猜测清理可能仍有原生引用的上游定义。启停只改变元信息；执行器在发布副本中排除停用资源，原文仍留在修订中。新建 HTTP/Stream 默认使用受管 JSON 日志格式，排除查询参数、凭据与业务载荷。日志轮转、查询及保留策略继续在 P2 接入。

访问列表原文位于 `security/acl/<UUID>.conf`，含受管名称/备注注释，规则是有序 IP/CIDR 加明确的末条允许或拒绝。列表可被多个 HTTP 代理引用；修改保存为统一修订，应用流程不另设入口。混合规则只读，存在原生规则或子路径覆盖时不允许表单绑定；删除要求先解除全部 include 引用。安全写入检查新旧期望树及被替换的已生效树，不能通过删除最后一条安全指令绕过 `security.write`。

配置树 `base_version` 指向当前有效期望状态；草稿使用独立不可变修订，不改变该版本。错误草稿没有有效投影、不会创建任务。保存不等于实际应用。`validate` 创建真实 `nginx -t` 任务，不改变运行修订；`apply` 创建应用任务，也可用 `/nginx/apply` 应用已保存修订。两者互斥且不能用于草稿。执行保留幂等操作标识、提交意图及 Agent 接受记录；超时先查询独立执行记录，已接受记录缺失时转为恢复状态。任务终态和已观察修订同事务记录，只有确认成功或确认回滚才更新 `config_head.applied_revision`。

Agent 只监听 Unix Socket，使用 `SO_PEERCRED` 校验唯一授权 UID。生产 Agent 要求 root；开发 Agent 不执行宿主机写操作。Agent 不访问业务数据库。策略默认不允许外部 include、任意路径、动态模块、Lua/JS/Perl、任意文件服务与可执行扩展。未来开放系统只读 include 或模块必须通过 root 策略清单，不能由 API 放宽。Nginx 执行仅由本机 root 参数启用；worker 与 Web 使用不同的非 root 账户。`nginx-init` 只生成无站点基线，不启动或接管已有服务。执行器验证固定二进制、PID 及实际启动参数，通过 pidfd 向专用主进程发送 HUP。

发布保留数据库原文，只对生成副本注入独立 Unix Socket 修订探针、可信运行身份/临时路径和受管日志格式，并将 include 固定到不可变修订目录。受管缓存使用固定独立目录和预算，默认绕过凭据/Cookie 请求及带 Set-Cookie 的响应；HTTPS 上游默认启用证书与 SNI 校验，未指定全局 CA 时固定一份可信系统 CA 快照。源文件、发布文件与证书依赖分别校验散列；外部修改暂停覆盖。先持久化切换意图再原子切换 active，新的本地连接确认修订、主进程监听归属及 HTTPS 证书指纹；UDP 仅确认监听，不冒充应用层健康。未确认切换在 Agent 重启后恢复上一受管修订，无法证明恢复时保留 `recovery_required`。

Agent 操作记录使用独立文件、原子 rename、文件与目录 fsync。记录只含操作 ID、输入摘要、修订、阶段与期限，不含原文、秘密或日志载荷；最多 2048 条，达到上限须本机维护，不能无界写入。未来 DNS/防火墙流程必须在副作用前持久化旧状态与期限，确认或补偿由 Agent 独立完成，重启先恢复未确认操作，恢复记录不进入业务备份。尚未接入这些适配器时不得开放写入。

组件信任合同：来源、固定版本、架构、ABI、文件散列和许可证进入签名清单；root 独占激活目录。安装、启用、启动与卸载是不同动作；系统组件不自动迁移或替换。实际组件安装/升级及健康检查在 P4 接入，当前不接受任意组件包或系统软件安装请求。

资源预算见 `internal/limits`。配置树最多 128 文件、单文件 256 KiB、总计 2 MiB、嵌套 32 层；发布目录最多 128 个修订，监听/TLS 确认各最多 256 项，证书文件引用最多 128；HTTP/IPC 请求最多 4 MiB；任务排队最多 100，当前单 worker；列表每页最多 100。监控、日志、暂存、备份与 SSE 的初始预算已固定，启用对应功能时必须在实际入口执行，常量本身不代表该功能已经交付。

DNS 能力诊断只给出候选所有者，尚未验证的所有组合只读。工具已安装、模块启用、服务运行、系统兼容性验收是独立事实；未知运行状态返回 null。未接入 Agent 时，Web 不展示容器/本进程环境为宿主机事实。
