## 引导安装、管理脚本与容器构建

**实现完成，待集中验证。** 已增加根目录引导安装器和管理菜单/命令，复用现有标准安装器，支持原生/Docker、Nginx 来源及可选宿主机授权。引导安装保存 root 保护的原安装命令与批准材料，失败后按原参数续装；管理脚本按实际安装记录选择 systemd/Compose，支持启停、状态、日志、首次访问和远程入口救援，并保留持久停机/恢复屏障。

引导安装已改为自动检测目标系统、CPU 架构、随包材料、本机 Docker、匹配镜像、可信 Nginx、可用数据目录及管理端口，默认推荐并启动可用方案；自定义参数与主机写入授权放入高级设置。Docker 安装和管理固定连接本机 socket。构建的默认示例改为无参数执行，自动识别构建机架构，只有跨架构目标需要覆盖。

安装入口已简化为两条闭环：源码目录执行 `sudo bash install.sh --yes` 自动容器构建、解包、安装；独立 `setup.sh` 按本机架构下载 GitHub Release、核对 SHA-256 后安装，也支持 `--source` 自动拉取源码。普通安装采用自动推荐，仅 `--advanced` 打开逐项配置；不带 `--yes` 时保留最终摘要确认。发布暂存将安装器和管理脚本纳入原面板签名归档，上传阶段生成内置仓库与标签的下载脚本，并补齐校验清单。无独立安装包体系；尚未执行真实线上发布。

已增加 Docker 构建入口，读取项目固定工具版本，在容器内生成 amd64/arm64 安装包；源码复制到构建上下文，宿主机只接收产物。`make build` 与 `make release-tool` 均使用该入口。Docker 服务启动要求镜像已经准备，不隐式拉取或增装 Nginx 模块。

## 明确的支持边界

以下限制需要保留在能力报告中，不能静默视为成功；也不能未经需求确认把它们全部扩大为首版新功能：

- Docker 原生 nftables 为实验只读；默认已支持并验收的 Docker iptables 转发路径与其不同。
- rootless、Swarm，以及未能证明 Docker 实例/后端/流量 hook 的组合不开放发布端口写入。
- DNS 不明所有者、无法安全映射的动态配置保持只读，不接管任意系统网络管理器。
- 已有 Fail2ban 自动接管仅限审查过的固定配置；任意自定义过滤器/动作、随机或递增封禁等不自动接管。
- Python 的 APT 依赖计划只接受可信的直接 HTTP(S) 包地址；`mirror+file` 等间接来源明确拒绝，不自动改写宿主机软件源。
- 迁移传递业务期望与必要配置，不复制源主机二进制、动态模块、root 授权或源任务执行资格。
- 模块缺失通过受信组件/固定模块镜像解决，禁止部署时临时编译或增装 Nginx 模块。
