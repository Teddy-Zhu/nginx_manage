## 明确的支持边界

以下限制需要保留在能力报告中，不能静默视为成功；也不能未经需求确认把它们全部扩大为首版新功能：

- Docker 原生 nftables 为实验只读；默认已支持并验收的 Docker iptables 转发路径与其不同。
- rootless、Swarm，以及未能证明 Docker 实例/后端/流量 hook 的组合不开放发布端口写入。
- DNS 不明所有者、无法安全映射的动态配置保持只读，不接管任意系统网络管理器。
- 已有 Fail2ban 自动接管仅限审查过的固定配置；任意自定义过滤器/动作、随机或递增封禁等不自动接管。
- Python 的 APT 依赖计划只接受可信的直接 HTTP(S) 包地址；`mirror+file` 等间接来源明确拒绝，不自动改写宿主机软件源。
- 迁移传递业务期望与必要配置，不复制源主机二进制、动态模块、root 授权或源任务执行资格。
- 模块缺失通过受信组件/固定模块镜像解决，禁止部署时临时编译或增装 Nginx 模块。
