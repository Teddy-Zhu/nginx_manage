# FRP 服务端

在“软件商店 → 系统商店”中选择“FRP 服务端”，或打开“服务器管理 → FRP 服务端”。系统仅预置入口，不会自动安装。只提供服务端 frps；客户端 frpc 在需要接入的设备上自行部署。

## 安装与连接

1. 点击“安装”，确认客户端连接端口和访问密钥。默认监听 `0.0.0.0:7000`、开机自动启动，并仅允许加密连接。
2. 设置客户端可以映射的端口。默认允许 `10000–20000`，可以逐项添加单个端口或范围，也可以明确选择不限制。重复、重叠或包含服务连接端口、网站转发端口的范围会被拒绝。
3. 保存访问密钥后点击“安装并启动”。下载、配置检查和启动结果会显示在操作日志中。
4. 在防火墙中放通连接端口和实际需要对外提供的映射端口；系统不会自动覆盖现有规则。云服务器还需要相应放通安全组。
5. 在客户端配置服务器地址、端口和相同的密钥。页面显示连接地址、在线客户端、映射数量、连接数和累计流量，状态经统一 WebSocket 推送。

例如客户端使用如下原生 TOML 配置，将客户端本机 `127.0.0.1:8080` 映射到服务器的 `10080`：

```toml
serverAddr = "服务器公网或内网地址"
serverPort = 7000
auth.method = "token"
auth.token = "安装时设置的访问密钥"
transport.tls.enable = true

[[proxies]]
name = "my-web"
type = "tcp"
localIP = "127.0.0.1"
localPort = 8080
remotePort = 10080
```

UDP 映射使用 `type = "udp"`。允许映射的端口范围同时约束 TCP 和 UDP。客户端参数详见 [FRP 官方文档](https://gofrp.org/en/docs/reference/client-configures/)。

## 网站转发

在“服务设置”中分别启用 HTTP、HTTPS 网站转发并填写入口端口；未启用时不占用这些端口。客户端可使用 `http` 或 `https` 映射，并通过 `customDomains` 指定域名。DNS 需指向 FRP 服务器，防火墙需放通对应入口。

如果设置子域名后缀，例如 `example.com`，可以将 `*.example.com` 解析到服务器，再在客户端映射中设置 `subdomain = "app"`。使用该后缀的域名应填写 `subdomain`，不要同时填入 `customDomains`。HTTPS 转发由客户端提供 HTTPS 服务，服务端本页不申请或部署网站证书。

已有 Nginx 使用 80/443 时，请为 FRP 选择其他网站入口端口。系统检测端口占用，不会停止其他服务或修改 Nginx 配置。

## 设置与维护

- 设置通过弹窗编辑，保存前检查原生配置和监听端口。运行中的服务应用设置后重启，客户端会重新连接；已停止的服务保存设置后保持停止。
- 访问密钥不在状态或任务接口中回传。安装时请保存；修改设置时留空保留原密钥，生成或填写新密钥后，客户端需要同步更换。
- 启动、停止、重启、更新、查看日志和卸载沿用软件商店统一操作。卸载仅移除本面板管理的容器，保留设置与密钥供重装。
- 开机自动启动使用 Docker 的 `unless-stopped` 策略：正常运行时随主机启动，用户主动停止后保持停止。
- 更新拉取设置中的下载来源并重新创建服务；失败时恢复原配置及原服务，已停止的服务更新后保持停止。

内置使用 [FRP 官方发布镜像](https://github.com/fatedier/frp/pkgs/container/frps) `ghcr.io/fatedier/frps:v0.71.1`。可以通过下载来源更换兼容的 FRP 服务端镜像。Docker 原生配置由内置适配器维护，第三方软件源格式不受影响。

服务使用宿主网络以支持按需创建映射端口。仅管理带有本面板归属标识的 `nginxpanel-frps` 容器，拒绝接管同名外部容器。配置保存在数据目录的 `agent/frps/` 下；内部状态接口仅监听本机回环地址，并使用独立随机凭据，不对外提供原生控制台。
