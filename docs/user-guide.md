# 使用手册

[文档首页](README.md) · [部署指南](deployment.md) · [运维与故障处理](operations.md)

本文假定已完成部署和管理员初始化。涉及宿主机写入的功能，还需要目标本机管理员完成对应授权。

## 先理解操作状态

| 概念 | 含义 |
| --- | --- |
| 当前节点 | 本次页面操作的目标；切换节点前核对名称和永久编号 |
| 草稿 | 尚未成为有效期望配置的编辑内容 |
| 期望修订 | 已保存的业务配置，不表示已在 Nginx 生效 |
| 已应用修订 | 经执行器发布并完成运行确认的配置 |
| 功能模块启用 | 允许使用该管理功能，不代表已安装、启动或接管底层服务 |
| 计划/预检 | 检查目标、影响和前置条件；通常不执行实际变更 |
| 异步任务 | 后台操作记录；排队、执行、恢复中和成功是不同状态 |
| 待恢复 | 结果尚未明确或补偿尚未完成，需要沿原任务核对 |

首次使用从“概览”核对 Agent、Nginx、期望修订和已应用修订。按钮不可用时先查看具体原因，常见为缺权限、模块停用、未授权、组件缺失、外部冲突或存在未完成任务。

敏感操作会要求重新输入管理员密码。重新认证不会自动授予额外权限。

## 创建第一个 HTTP 代理

示例将目标主机的 8080 端口转发到同机已运行的 `http://127.0.0.1:3000`。请替换为自己的上游和域名；8080 应未被其他服务占用。

1. 打开“Nginx 配置”，选择“新建代理配置”。
2. 填写名称，例如 `demo-web`。
3. 类型选择“HTTP 反向代理”。
4. 监听填 `8080`；需要 IPv6 时另起一行填 `[::]:8080`。
5. 域名填实际业务域名，例如 `app.example.com`；多个域名以空格分隔。
6. 上游地址填 `http://127.0.0.1:3000`；单一上游时可留空“可选上游组成员”。
7. 保存配置，查看生成内容、启用状态、差异和诊断。
8. 选择“应用已保存修订”，等待任务完成并核对已应用修订。
9. 从业务入口访问该域名和端口，确认请求到达预期上游。

Docker 配套 Nginx 使用 host network，`127.0.0.1` 指向目标宿主机的回环网络；其他部署或外部上游按真实网络地址填写。目标到上游的可达性与外部客户端到代理的可达性分别判断。

使用 HTTPS 上游时，地址中的主机名参与上游 TLS 校验，应与其证书一致。

### 常用字段与上游组

选择站点后，可修改受支持的域名、监听、上游、超时等常用字段。“保存字段”生成新的配置修订，再按正常流程应用。

需要上游组时，在创建表单逐行填写成员，例如：

```text
127.0.0.1:3000 weight=2
127.0.0.1:3001 weight=1
```

保存后查看生成的 upstream 内容。复杂指令或当前字段编辑器不支持的组合使用原文编辑；系统不把无法可靠识别的原文强行转换成简单表单。

### TCP 与 UDP

在同一创建入口选择“TCP / UDP Stream”：

- TCP 示例：监听 `5433`，上游 `127.0.0.1:5432`。
- UDP 示例：监听 `5353 udp`，上游填实际 UDP 服务的 `地址:端口`。
- IPv6 监听使用 `[::]:端口`，不同监听逐行填写。

目标 Nginx 须具备 Stream 及配置所需模块。保存、检查和应用流程与 HTTP 相同；UDP 应使用实际业务客户端判断结果。

## 配置原文、草稿与回滚

“Nginx 配置”同时提供文件树、原文与常用字段。修改原文后：

- “保存草稿”用于保留尚未生效的编辑。
- “保存并校验”用于保存并获得配置检查结果；是否生效仍看运行状态。
- “保存有效修订”更新期望配置。
- “保存并应用”同时发起后续应用流程，最终结果仍看任务。

原文有未保存修改时，先处理该内容再编辑常用字段。文件使用受管相对路径；外部文件、任意宿主机路径或未知模块不会因粘贴进配置而取得授权。

需要回到旧配置时，从修订历史选择仍保有材料的版本加载原文，核对后保存为新修订并应用。旧修订和审计记录保留。应用失败或检测到外部变更时，按[配置恢复流程](operations.md#配置应用失败或外部变更)处理。

## 配置 HTTPS

### 导入已有证书

1. 打开“证书”，导入 PEM 证书链与匹配私钥，填写识别名称。
2. 检查证书域名、有效期、链和版本；续签材料导入为新的不可变版本。
3. 在“Nginx 配置”选择 HTTP 站点，设置证书及对应版本，按需使用“添加 443 HTTPS 监听”。
4. 根据业务设置 HTTP 跳转和 HSTS，保存并应用配置。
5. 在“证书部署”查看实际绑定与部署任务，核对业务 HTTPS 结果。

证书已导入或已签发，不代表运行实例已使用它。HSTS 会影响客户端后续访问，只在 HTTPS 配置稳定并符合业务需求时启用。

### 申请 ACME 证书

从证书相关页面进入“ACME 设置”，创建账户并选择测试或生产环境，填写联系邮箱并确认服务条款。DNS-01 还需保存对应服务商凭据：

| 服务商 | 凭据字段 |
| --- | --- |
| Cloudflare | `api_token`；可选独立 `zone_token` |
| 阿里云 DNS | `access_key_id`、`access_key_secret` |
| 腾讯云 DNSPod | `secret_id`、`secret_key` |

在“ACME 签发”创建签发配置，填写账户、域名和挑战方式：

- HTTP-01：域名正确指向目标，CA 可从公网 TCP 80 访问挑战，确认页面中的公网条件。云安全组和外部代理也需允许挑战路径。
- DNS-01：选择有权读取该测试域并增删挑战 TXT 记录的凭据；传播等待和清理由原订单任务记录。通配域名使用 DNS-01。

发起签发后查询原订单。失败或中断时优先续办、核对和清理原订单，避免重复创建仍未结束的挑战。

证书签发完成后，先在 Nginx 站点建立初始证书绑定并应用；再按需为签发配置启用自动续期和自动部署。自动部署更新已有绑定，签发结果和部署结果分别显示。

当前真实 CA、各 DNS 服务商的外部验收状态见[进度清单](progress.md)，不将页面支持视作全部实网场景已通过。

## 访问控制与基础 WAF

在“访问列表”维护可复用的 IPv4、IPv6、CIDR 规则，在“基础 WAF”创建站点防护策略、限流及路径规则。将策略引用配置到站点，保存并应用 Nginx 修订后生效。

调整策略前核对允许/拒绝顺序、实际客户端地址和业务路径。经过 CDN 或反向代理时，真实客户端地址只信任明确批准的来源链路；任意请求中的转发头不能直接视为真实来源。

基础 WAF 提供当前支持的规则能力，复杂业务条件应结合生成配置及实际需求判断。

## 主机功能

### 模块开关

在“功能模块”启用所需管理入口。启用不自动安装组件、不修改网络，也不自动接管已有服务；停用管理入口同样不代表底层保护或服务已停止。

### 服务器与监控

“服务器”查看目标宿主机资源与趋势，按页面支持的指标配置阈值和告警。明确区分宿主机指标与容器内部数据；数据不可用时查看来源和采集错误。

### 主机 DNS

首次安装须批准实际 DNS 所有者。打开“主机 DNS”，核对当前接口、配置来源和解析器状态，再生成计划、暂用候选并在期限内确认；不确认时按原快照恢复。

存在 DHCP、IPv6 RA、WireGuard 或分域 DNS 时保留它们的作用范围，仅修改计划中明确的 DNS 项。来源不明、接口映射不清或适配条件不满足时保持只读。

### 防火墙

1. “防火墙”查看实际后端、宿主机范围、Docker 路径和本机授权状态。
2. 本机 root 按[防火墙参考](firewall.md)完成所选后端登记；首次安装时还需选择对应后端和 SSH 保护方式。
3. 在“防火墙规则”保存期望规则并查看编译预览。
4. 直接连接目标节点的受控管理入口，在“防火墙应用”生成计划，核对 SSH、管理入口和来源保护。
5. 提交后用新连接在页面期限内确认；结果未知时查询原操作或请求回滚。

防火墙应用是本机操作，普通远程节点切换不能代替新连接确认。Docker 发布端口需独立授权并绑定实际容器映射；宿主机 INPUT 成功不代表 Docker 转发已受保护。Docker 原生 nftables 实验后端当前只读。

### Fail2ban

“Fail2ban”显示依赖、实例、jail、运行封禁和任务。可选择本应用的受管独立实例，或由 root 显式接入已有系统实例。

- 新实例：先准备签名组件及受支持 Python，预览安装，再分别选择启动与开机启用。
- 已有实例：只读接入、jail 接管和全局服务控制分别授权；服务控制影响该实例全部 jail。
- jail：保存期望、生成预览并应用；手动封禁/解封按当前登记及实时运行结果判断。
- 停用：区分管理模块停用、jail 停用、服务停止和开机禁用。

已有实例接入命令、当前允许接管的 SSH profile、保护来源和恢复过程见[Fail2ban 参考](fail2ban.md)。不支持的自定义配置保持明确的受限状态。

## 日志、通知与任务

“日志”按来源、时间和页面支持的条件查询应用、安全、任务及 Nginx 日志，可下载或实时跟随。轮转后旧游标或连接失效时，重新查询有效时间段；断开的实时流不代表期间没有日志。

“轮转与保留”需要日志唯一所有者已在本机批准为 Agent；默认未确认和 external 模式保持只读。下载内容仍按敏感信息保管。

“通知”创建 Webhook 或 Telegram 渠道，选择订阅事件并明确启用。Webhook 支持配置 Bearer 与 HMAC；Telegram 填写 Bot Token、目标 chat ID，按需指定话题 ID。渠道测试和真实消息均会产生投递记录；查看待发、已接收、重试、失败或过期状态。Webhook 接收方应按稳定幂等标识去重。

“任务与审计”用于核对操作者、阶段、错误和最终结果。页面断连后先查原任务；`recovery_required` 表示需要沿原操作恢复，不以重新点击创建新任务来覆盖。

## 从本地迁移到云端

目标先部署本系统并完成管理员初始化、HTTPS 信任和所需本机授权。两种常用方式：

### 导出文件后导入

1. 源节点“配置迁移”选择导出方式和材料。
2. 普通可移植包只保留可识别的受管字段，导入站点停用；有完整原文或秘密需求时选择加密包。
3. 加密包口令为 16–256 字节，与文件分开传递和保管。
4. 在目标导入，填写监听、域名、上游、模块路径及按需的主机配置映射。
5. 阅读依赖和冲突结果，处理缺失组件；签名组件准备和首次安装须明确授权。
6. 重新预检后选择草稿、保存或应用，跟随任务至明确结果。
7. 核对目标业务入口后安排域名/流量切换。迁移后再按需启用续期、部署或通知。

### 使用对方 API 一键迁移

可在目标“配置迁移”从源节点拉取，也可在源节点“迁出到节点”推送到目标。填写对方 HTTPS API 地址、专用 API Key；自签名证书需填写独立核对的证书 SHA-256 指纹。

首次先选预览，核对目标身份、权限、基础版本、映射和依赖，再明确选择执行模式。Key 权限按方向不同，具体字段及授权见[迁移参考](migration.md#源端推送式一键迁出)。

需要改变目标、映射或执行模式时创建新计划；网络中断且结果未知时先查询原计划，沿原任务续办。迁移不复制源主机二进制、模块、root 授权、管理员、节点身份或管理入口；目标缺失能力须按目标条件处理。

## 完整备份与恢复

“完整备份”固定操作本机。手动备份选择 age 公钥或口令加密，任务完成后下载并核对页面记录的 SHA-256，将文件保存到独立设备。

定期备份使用 age X25519 公钥。私钥在离线设备生成和保管，面板只保存公钥；保存周期、保留策略及明确的授权期限。定期检查授权是否过期，下载留存所需备份。

完整备份包含数据库、配套主密钥、管理员及主入口 TLS 等敏感材料。跨环境搬业务配置使用前述迁移流程；完整恢复需要目标停机、独立回退快照、依赖检查和最终激活，按[恢复顺序](operations.md#完整备份恢复)操作。

## 管理多个节点

在目标节点“设置”签发限定权限、来源和期限的机器凭据，再在控制节点“节点连接”填写目标 HTTPS 地址、API Key 及证书指纹；也可使用短期一次性配对。

连接后通过节点选择器切换业务操作目标，核对永久编号。目标不可达、身份变化或授权失效时，先修复原连接。删除连接后查看远端授权撤销结果，待核对时在目标补做撤销。

设置、节点连接、管理入口、完整备份等本机页面按页面标识操作。详细权限交集、配对、删除和转发边界见[多节点](nodes.md)。

## 账户与 API

在“设置”修改管理员密码、撤销会话及创建/撤销机器凭据。修改密码会撤销浏览器会话；Token 只在创建时展示，立即保存到受限文件，遗失后重新签发。

API 基础路径为 `/api/v1`，机器使用 Bearer，浏览器使用 Cookie 与 CSRF。JSON 响应统一为：

```json
{
  "code": "OK",
  "message": "操作成功",
  "data": {},
  "request_id": "请求编号",
  "node_id": "实际响应节点编号"
}
```

HTTP 状态保留语义；异步 `202` 只表示已受理，按返回任务标识继续查询。版本冲突需重新读取；写请求按合同提供 `Idempotency-Key`，同一操作重试沿用原键，同键不能更换内容。

例如，用只读凭据查询当前防火墙期望策略。将下列配置保存在本地 0600 文件 `nginxpanel-read.curl`，替换 Token 与已核对的入口证书路径：

```text
header = "Authorization: Bearer <只读Token>"
cacert = "/安全目录/已核对的入口证书.pem"
```

```sh
curl --config ./nginxpanel-read.curl --silent --show-error --fail-with-body \
  https://127.0.0.1:9443/api/v1/firewall/policy
```

示例通过部署指南的 SSH 转发访问回环入口；更换远程地址时使用对应 HTTPS 证书。完整接口、权限和各输入模型见[API 合同](../api/openapi.yaml)。

## 组件和版本管理

“组件准备”只下载/检查签名资产；“组件安装”用于原生 Nginx 首次安装；“组件切换”用于已装原生 Nginx 维护换包；“面板更新”和“Agent 升级”管理各自版本；“运行镜像”和“Nginx 镜像”用于 Docker 对应镜像替换。

更新前完整备份、阅读已验签发行说明，按页面进入“配置维护”，核对中断范围并提交。完成或恢复确认后释放原维护会话。详细顺序和异常处理见[运维文档](operations.md#组件准备与更新)。

“历史维护”只清理页面预览允许删除且已不再被引用的材料。先备份、核对预览，再明确执行；当前使用或恢复仍需的材料保留。
