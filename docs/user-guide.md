# 使用手册

[文档首页](README.md) · [部署指南](deployment.md) · [运维与故障处理](operations.md)

本文假定已完成安装和管理员初始化。安装器自动识别受支持的主机网络环境，基础监控、DNS 和防火墙功能默认开启；无法支持的配置会显示具体原因。

## 从哪里开始

| 页面 | 常用操作 |
| --- | --- |
| 概览 | 查看 CPU、内存、Nginx 状态和最近任务 |
| 网站与代理 | 添加网站或反向代理，修改域名、端口和上游 |
| SSL 证书 | 申请、上传和更新证书 |
| 软件商店 | 安装和管理 Nginx、登录防护及第三方软件 |
| Docker 容器 | 查看容器、启停服务、重启和读取运行日志 |
| 防火墙、DNS 设置、监控 | 管理服务器网络和查看资源使用情况 |
| 备份恢复、配置迁移 | 备份数据，或在服务器间迁移配置 |
| 设置 | 修改密码、设置安全访问和更新系统 |

保存配置后，点击对应的应用按钮使其生效。后台操作可在“任务与操作记录”查看进度；登录会话有效期间无需重复输入管理员密码，冲突覆盖及高影响操作仍需确认。只有明确成功的任务才表示操作完成。

日常操作无需选择操作系统或底层网络管理器。页面提供配置表单、操作入口和日志；Nginx 源文件编辑保留在其高级配置中。

## Docker 容器管理

在“系统管理 → Docker 容器”查看当前服务器的全部容器，可按名称、镜像或项目搜索，并按运行状态筛选。容器详情包含镜像、创建时间、自动重启策略、端口、网络及数据挂载。

运行中的容器可以停止或重启；停止或尚未启动的容器可以启动。操作进度和结果显示在任务日志中，列表自动更新。停止容器前需确认，避免中断正在使用的服务。面板自身的系统容器禁止在此启停。

点击“日志”查看最近的运行日志，可调整行数、暂停更新及复制内容。关闭日志窗口后停止对应日志订阅。列表和日志沿用全局实时连接；Docker 服务不可用时会显示原因。

## 安装所需软件

未安装软件时，相关页面统一显示安装入口。点击后进入“软件商店”，不会自动安装其他可选软件。

安装 Nginx 时，查找可用版本并下载安装包，系统自动匹配服务器环境。点击“开始安装”后，面板暂停配置修改、等待当前任务结束，再完成安装；默认立即启动并设置开机启动。

安装登录防护时，在 Fail2ban 卡片点击“安装”，系统自动开启对应功能并准备防护环境；无需手动安装运行依赖。完成后点击“打开”进入登录防护页面添加规则；“软件管理”负责启停、更新和卸载。

安装第三方软件时，先添加软件源，再选择软件点击“安装”。导入软件源本身不会自动安装软件。安装状态和失败原因均可在任务日志查看；安装中断后可回到软件商店处理。

内置 Fail2ban 使用预置 Docker 镜像安装，不依赖本项目的 GitHub Release，也无需在宿主机安装 Python 或编译。第三方软件可导入软件源后按需安装，详见[软件源说明](software-sources.md)。操作进度和失败原因可在对应日志查看。

## 创建第一个 HTTP 代理

示例将目标主机的 8080 端口转发到同机已运行的 `http://127.0.0.1:3000`。请替换为自己的上游和域名；8080 应未被其他服务占用。

1. 打开“网站与代理”，选择“添加网站 / 代理”。
2. 填写名称，例如 `demo-web`。
3. 类型选择“HTTP 反向代理”。
4. 监听端口填 `8080`，地址留空表示全部网卡；需要 IPv6 时点击“添加监听”，地址填 `::`，端口填 `8080`。
5. 添加实际业务域名，例如 `app.example.com`；多个域名使用“添加域名”逐项填写。
6. 转发目标选择“网站或单一后端”，目标网站地址填 `http://127.0.0.1:3000`。默认以目标网站域名转发 Host；后端需要原访问域名时，选择“保留访问域名”。
7. 保存配置，核对站点的启用状态和保存结果。
8. 选择“应用配置”，等待任务完成并确认显示“已生效”。
9. 从业务入口访问该域名和端口，确认请求到达预期上游。

Docker 配套 Nginx 使用 host network，`127.0.0.1` 指向目标宿主机的回环网络；其他部署或外部上游按真实网络地址填写。目标到上游的可达性与外部客户端到代理的可达性分别判断。

使用 HTTPS 上游时，地址中的主机名参与上游 TLS 校验，应与其证书一致。

### 常用字段与上游组

选择站点后，可修改受支持的域名、监听、上游、超时等常用字段。点击“保存配置”，再按正常流程应用配置。域名、监听和可信来源可逐项添加；大小和超时分别选择数值与单位，请求头分别填写名称和值。

需要多个后端时，转发目标选择“Upstream 上游组”，逐项添加后端地址和端口，再设置权重、失败次数、重试间隔和备用状态。IPv6 地址直接填写，无需添加方括号。后端网站地址指定协议、Host 域名与路径；HTTPS 域名还用于证书校验。已有单一后端可点击“配置 Upstream 上游组”，保存后直接转换；已创建的组可在同一站点表格中编辑成员。每个站点独立管理自己的上游组。

后端支持 WebSocket 时，点击“启用 WebSocket”，再保存并应用。该预设配置 Upgrade 转发并将读取超时设为一小时。流式接口可使用“SSE / 流式响应”预设。

复杂指令或当前字段编辑器不支持的组合从“更多操作 → 编辑源文件”调整；系统不把无法可靠识别的原文强行转换成简单表单。

### 网站 IP 与国家黑白名单

打开“网站访问控制”，新建规则并选择黑名单或白名单。填写 IP/CIDR，或选择国家和地区；同一规则中匹配任一 IP 或国家即视为命中。黑名单拒绝命中来源，白名单仅放行命中来源；空白名单拒绝全部来源，未知国家和内网地址仅按手填 IP 匹配。

国家规则使用与防火墙共享的 GeoIP 数据源。首次使用先在“管理数据源”中更新数据，支持默认 GitHub MMDB 或自定义 MMDB/CIDR 来源。保存规则后，在“网站与代理”选择该站点的访问列表，再保存并应用；其他站点不受影响。

国家网段随规则保存为快照，Nginx 使用预置的 `geo` 模块查询 IPv4/IPv6。更新数据源不会直接改变已发布的网站；重新保存并应用对应规则后生效。通过 CDN 或其他代理访问时，只在“可信代理来源”中填写实际代理网段，并设置相应真实 IP 请求头；普通客户端提供的转发头不会自动成为可信来源。

### TCP 与 UDP

在同一创建入口选择“TCP / UDP Stream”：

- TCP 示例：监听端口填 `5433`，后端地址填 `127.0.0.1`，后端端口填 `5432`。
- UDP 示例：监听端口填 `5353`，在监听选项中选择“UDP”，分别填写后端地址和端口。
- IPv6 监听地址直接填 `::`；多个监听使用“添加监听”逐项配置。

目标 Nginx 须具备 Stream 及配置所需模块。保存、检查和应用流程与 HTTP 相同；UDP 应使用实际业务客户端判断结果。

## 配置原文与应用

“网站与代理”默认使用可视化表单。需要调整源文件时，展开“更多操作”并点击“编辑源文件”，在弹窗中选择文件；关闭弹窗会保留尚未保存的内容。修改原文后：

- “保存并校验”用于保存并获得配置检查结果；是否生效仍看运行状态。
- “保存配置”保存修改，之后点击“应用配置”生效。
- “保存并应用”同时发起后续应用流程，最终结果仍看任务。

原文有未保存修改时，先处理该内容再编辑常用字段。文件使用受管相对路径；外部文件、任意宿主机路径或未知模块不会因粘贴进配置而取得授权。

“更多操作”中的“配置差异”可比较当前编辑内容与已保存或已生效的配置。页面不提供配置历史版本选择与恢复。应用失败或检测到外部变更时，按[配置恢复流程](operations.md#配置应用失败或外部变更)处理。

## 配置 HTTPS

### 导入已有证书

1. 打开“证书”，导入 PEM 证书链与匹配私钥，填写识别名称。
2. 检查证书域名、有效期和信任状态；已有证书可使用“更新证书”导入续签材料。
3. 在“网站与代理”选择 HTTP 站点，选择证书，按需使用“添加 443 HTTPS 监听”。
4. 根据业务设置 HTTP 跳转和 HSTS，保存并应用配置。
5. 在“网站证书”查看正在使用此证书的网站及更新记录，核对业务 HTTPS 结果。

证书已导入或已签发，不代表运行实例已使用它。HSTS 会影响客户端后续访问，只在 HTTPS 配置稳定并符合业务需求时启用。

### 申请 ACME 证书

证书页面顶部统一分为“我的证书”“申请与续期”“网站证书”“申请设置”。点击“申请证书”开始；尚无申请账户时，页面会引导创建账户，完成后返回申请。默认申请正式证书，测试证书用于调试，不受浏览器信任。DNS 验证还需在“申请设置 → DNS 授权”保存服务商授权：

| 服务商 | 凭据字段 |
| --- | --- |
| Cloudflare | `api_token`；可选独立 `zone_token` |
| 阿里云 DNS | `access_key_id`、`access_key_secret` |
| 腾讯云 DNSPod | `secret_id`、`secret_key` |

在“ACME 签发”创建签发配置，填写账户、域名和挑战方式：

- HTTP-01：域名正确指向目标，CA 可从公网 TCP 80 访问挑战，确认页面中的公网条件。云安全组和外部代理也需允许挑战路径。
- DNS-01：选择有权读取该测试域并增删挑战 TXT 记录的凭据；传播等待和清理由原订单任务记录。通配域名使用 DNS-01。

填写多个域名时逐项添加，选择验证方式后点击“申请证书”，系统自动提交申请并提供日志。发起签发后查看申请记录和原订单。失败或中断时优先续办、核对和清理原订单，避免重复创建仍未结束的挑战。

证书签发完成后，先在 Nginx 站点建立初始证书绑定并应用；再按需为签发配置启用自动续期和自动部署。自动部署更新已有绑定，签发结果和部署结果分别显示。

当前真实 CA、各 DNS 服务商的外部验收状态见[进度清单](progress.md)，不将页面支持视作全部实网场景已通过。

## 访问控制与基础 WAF

在“访问列表”维护可复用的 IPv4、IPv6、CIDR 规则，在“网站防护”创建站点防护策略、限流及路径规则。将策略引用配置到站点，保存并应用 Nginx 修订后生效。

调整策略前核对允许/拒绝顺序、实际客户端地址和业务路径。经过 CDN 或反向代理时，真实客户端地址只信任明确批准的来源链路；任意请求中的转发头不能直接视为真实来源。

基础 WAF 提供当前支持的规则能力，复杂业务条件应结合生成配置及实际需求判断。

## 主机功能

### 模块开关

在“功能模块”启用所需管理入口。启用不自动安装组件、不修改网络，也不自动接管已有服务；停用管理入口同样不代表底层保护或服务已停止。

### 服务器与监控

“服务器”查看目标宿主机资源与趋势，按页面支持的指标配置阈值和告警。明确区分宿主机指标与容器内部数据；数据不可用时查看来源和采集错误。

### 主机 DNS

打开“DNS 设置”，先查看当前配置；有多个网络接口时，选择需要修改的接口。启用 DNS 管理后点击“修改 DNS”，逐项填写 DNS 地址、可选的域名后缀和用于检查解析的测试域名。支持自动获取的网络可保留自动 DNS 并补充手动地址。

确认替换配置后点击“检查设置”，核对“当前设置”和“修改后”，再点击“应用 DNS 设置”。解析检查通过后，在 120 秒内点击“确认保留”；也可恢复原设置，超时会自动恢复。当前变更优先展示，执行结果可查看操作日志。状态通过共用实时连接更新。

存在 DHCP、IPv6 RA、WireGuard 或分域 DNS 时保留它们的作用范围，仅修改计划中明确的 DNS 项。来源不明、接口映射不清或适配条件不满足时保持只读。

### 防火墙

1. “防火墙”查看实际后端、宿主机范围、Docker 路径和本机授权状态。
2. 本机 root 按[防火墙参考](firewall.md)完成所选后端登记；首次安装时还需选择对应后端和 SSH 保护方式。
3. 在“防火墙规则”逐项添加来源地址，选择单个端口或端口范围，分别填写起始和结束端口，保存后查看预览。
4. 直接连接目标节点的受控管理入口，在“防火墙应用”生成计划，核对 SSH、管理入口和来源保护。
5. 提交后用新连接在页面期限内确认；结果未知时查询原操作或请求回滚。

防火墙应用是本机操作，普通远程节点切换不能代替新连接确认。Docker 发布端口需独立授权并绑定实际容器映射；宿主机 INPUT 成功不代表 Docker 转发已受保护。Docker 原生 nftables 实验后端当前只读。

### Fail2ban

在“软件商店 → 系统商店”找到 Fail2ban，点击“安装”，查看下载状态与安装日志。默认使用预置 Docker 镜像，并开启开机自动启动，可按需启动、停止、重启、更新或保留数据卸载。

进入“登录防护”，添加 SSH、面板登录或网站认证规则，选择保护端口、失败次数和封禁时间。信任名单支持逐项填写 IP 或网段；封禁名单可查看、添加或解除封禁。网站认证规则识别 HTTP 401，需要网站已启用并产生访问日志。

软件管理、规则变更及封禁操作均提供任务日志，页面通过全局 WebSocket 更新状态。详细部署范围及软件源配置见[软件源说明](software-sources.md)。

## 日志、通知与任务

“日志”按来源、时间和页面支持的条件查询应用、安全、任务及 Nginx 日志，可下载或实时跟随。轮转后旧游标或连接失效时，重新查询有效时间段；断开的实时流不代表期间没有日志。

“轮转与保留”默认管理本应用专用 Nginx 日志；选择已有外部工具轮转，或未获管理授权时保持只读。下载内容仍按敏感信息保管。

“通知”创建 Webhook 或 Telegram 渠道，选择订阅事件并明确启用。Webhook 支持配置 Bearer 与 HMAC；Telegram 填写 Bot Token、目标 chat ID，按需指定话题 ID。渠道测试和真实消息均会产生投递记录；查看待发、已接收、重试、失败或过期状态。Webhook 接收方应按稳定幂等标识去重。

“任务与操作记录”用于核对操作者、阶段、错误和最终结果。页面断连后先查原任务；`recovery_required` 表示需要沿原操作恢复，不以重新点击创建新任务来覆盖。

## 从本地迁移到云端

目标先部署本系统并完成管理员初始化、HTTPS 信任和所需本机授权。两种常用方式：

### 导出文件后导入

1. 源节点“配置迁移”选择导出方式和材料。
2. 普通可移植包只保留可识别的受管字段，导入站点停用；有完整原文或秘密需求时选择加密包。
3. 加密包口令为 16–256 字节，与文件分开传递和保管。
4. 在目标导入，填写监听、域名、上游、模块路径及按需的主机配置映射。
5. 阅读依赖和冲突结果，处理缺失组件；签名组件准备和首次安装须明确授权。
6. 重新预检后选择草稿、保存或应用，跟随任务至明确结果。
7. 核对目标业务入口后安排域名/流量切换。迁移后再按需启用续期、部署或通知。

### 使用对方 API 一键迁移

可在目标“配置迁移”从源节点拉取，也可在源节点“迁出到节点”推送到目标。填写对方 HTTPS API 地址和专用 API Key，证书校验由系统自动处理。

首次先选预览，核对目标身份、权限、基础版本、映射和依赖，再明确选择执行模式。Key 权限按方向不同，具体字段及授权见[迁移参考](migration.md#源端推送式一键迁出)。

需要改变目标、映射或执行模式时创建新计划；网络中断且结果未知时先查询原计划，沿原任务续办。迁移不复制源主机二进制、模块、root 授权、管理员、节点身份或管理入口；目标缺失能力须按目标条件处理。

## 完整备份与恢复

“备份恢复”固定操作本机。手动备份选择 age 公钥或口令加密，任务完成后下载并核对页面记录的 SHA-256，将文件保存到独立设备。

定期备份使用 age X25519 公钥。私钥在离线设备生成和保管，面板只保存公钥；保存周期、保留策略及明确的授权期限。定期检查授权是否过期，下载留存所需备份。

完整备份包含数据库、配套主密钥、管理员及主入口 TLS 等敏感材料。跨环境搬业务配置使用前述迁移流程；完整恢复需要目标停机、独立回退快照、依赖检查和最终激活，按[恢复顺序](operations.md#完整备份恢复)操作。

## 管理多个节点

在目标节点“设置”签发限定权限、来源和期限的机器凭据，再在控制节点“节点连接”填写连接名称、目标 HTTPS 地址和 API Key；也可使用短期一次性配对。

连接后通过节点选择器切换业务操作目标，核对永久编号。目标不可达、身份变化或授权失效时，先修复原连接。删除连接后查看远端授权撤销结果，待核对时在目标补做撤销。

设置、节点连接、管理入口、完整备份等本机页面按页面标识操作。详细权限交集、配对、删除和转发边界见[多节点](nodes.md)。

## 账户与 API

在“设置”修改管理员密码、撤销会话及创建/撤销机器凭据。修改密码会撤销浏览器会话；Token 只在创建时展示，立即保存到受限文件，遗失后重新签发。

API 基础路径为 `/api/v1`，机器使用 Bearer，浏览器使用 Cookie 与 CSRF。JSON 响应统一为：

```json
{
  "code": "OK",
  "message": "操作成功",
  "data": {},
  "request_id": "请求编号",
  "node_id": "实际响应节点编号"
}
```

HTTP 状态保留语义；异步 `202` 只表示已受理，按返回任务标识继续查询。版本冲突需重新读取；写请求按合同提供 `Idempotency-Key`，同一操作重试沿用原键，同键不能更换内容。

例如，用只读凭据查询当前防火墙期望策略。将下列配置保存在本地 0600 文件 `nginxpanel-read.curl`，替换 Token 与已核对的入口证书路径：

```text
header = "Authorization: Bearer <只读Token>"
cacert = "/安全目录/已核对的入口证书.pem"
```

```sh
curl --config ./nginxpanel-read.curl --silent --show-error --fail-with-body \
  https://127.0.0.1:9443/api/v1/firewall/policy
```

示例通过部署指南的 SSH 转发访问回环入口；更换远程地址时使用对应 HTTPS 证书。完整接口、权限和各输入模型见[API 合同](../api/openapi.yaml)。

## 软件管理与系统更新

“软件商店”分为“系统商店”和“第三方商店”，以软件卡片展示用途和安装状态，可搜索软件并筛选已安装或未安装项。卡片上的“软件管理”统一提供软件运行操作和日志，“打开”进入软件对应的功能页面。下载来源、开机启动等运行选项在软件管理中设置；网站、防护规则和 FRP 连接与映射在各自页面编辑。FRP 首次安装会跳转其页面填写连接信息。操作进度与日志可在“操作记录”查看。第三方软件源在“第三方商店 → 管理软件源”维护。第三方软件支持导入 JSON 文件或远程配置地址，按需安装、更新和卸载，具体格式见[软件源说明](software-sources.md)。

“设置 → 系统更新”提供检查、下载和立即更新。更新时短暂重启面板，启动后自动迁移数据。Docker 部署拉取并重新创建面板容器，原生部署切换程序并重启服务。更新前可先通过“备份恢复”创建备份。

“清理存储”只清理页面预览允许删除且已不再被引用的材料；当前使用的文件保留。

## 防火墙名单与 GeoIP

在“防火墙”添加端口规则、IP 黑白名单或国家和地区名单，选择放行或屏蔽。新建和编辑的规则放在列表顶部，也可以使用“置顶”调整顺序；访问范围重叠且动作不同时，保存前需确认覆盖。保存后点击“应用变更”，按页面提示确认新连接；超时会自动恢复。

名单的放行用于优先匹配本工具管理的规则。其他防火墙规则及云安全组继续生效，不会因为添加白名单而自动失效。国家名单及全协议 IP 名单使用 nftables 地址集合；已有其他管理方式仍保留端口与指定协议 IP 规则能力。

“GeoIP 数据”默认使用 GitHub 开源的 Loyalsoldier Country.mmdb，可修改下载地址或切换至 IPdeny。支持 MaxMind MMDB、每行一个网段的 CIDR 文本及 gzip 压缩文件。CIDR 下载地址用 `{country}` 代表小写国家代码，并选择需要更新的国家。内网 HTTPS 镜像需明确启用“允许从内网镜像下载”。

更新 GeoIP 数据后，当前页面的国家名单会重新解析；保存并应用防火墙变更后生效。数据源变更、下载失败或解析失败不会直接改变已生效规则。迁移包携带数据源配置与已解析名单快照，目标机器可继续手动更新数据。

## FRP 服务端

从软件商店按需安装 FRP 服务端，设置客户端连接端口、访问密钥和允许映射的端口。网站转发可单独启用 HTTP、HTTPS 入口。详见 [FRP 服务端使用说明](frps.md)。

## 导航与软件入口

- 概览：服务器概况和实时监控。
- 网站服务：网站与代理、SSL 证书、网站访问控制和网站防护。
- 软件应用：软件商店和 FRP 服务端。商店负责安装、启停、更新、卸载及运行设置；“打开”进入软件功能页。
- 安全防护：防火墙和登录防护。
- 系统管理：DNS 设置、日志、任务与操作记录、服务器连接。
- 数据与设置：备份恢复、配置迁移、通知和系统设置。

安装、版本切换及存储清理直接从对应页面发起，系统自动完成操作准备与收尾。中断的任务在操作记录中继续；不需要单独切换系统模式。
