# 软件源

软件商店分为“系统商店”和“第三方商店”，支持按软件名称、用途和安装状态筛选。系统商店提供 Nginx、Fail2ban、FRP 服务端等内置软件；第三方商店展示已添加软件源中的应用，并标明所属软件源和运行状态。默认只安装面板及必要的 Nginx；Fail2ban、FRP 和第三方软件均由用户点击安装。

## 内置 Fail2ban

Fail2ban 使用现成的 `crazymax/fail2ban:debian` 镜像部署，安装时不访问本项目的 GitHub Release，也不在宿主机安装 Python 或编译 Fail2ban。来源为 [crazy-max/docker-fail2ban](https://github.com/crazy-max/docker-fail2ban)。默认开启开机启动；安装、启停、更新和卸载都有任务状态与日志。

在“登录防护”添加 SSH、面板登录或网站认证规则，设置失败次数、统计时长、封禁时长及保护端口；信任名单支持 IP 和网段。封禁名单可查看并解除封禁，也可手动封禁地址。SSH 日志自动选择系统日志或认证日志；面板和网站使用本系统管理的日志。网站认证规则针对 HTTP 401，不能自动识别任意网站自定义的登录失败页面。

容器使用宿主网络及必要的 `NET_ADMIN`、`NET_RAW` 权限，读取日志并通过独立的 `NGINXPANEL_F2B` 规则链与 IPSet 地址集合限制受保护端口，不清空原有防火墙规则。每条规则最多保护 15 个 TCP 端口；IPv4 和 IPv6 分别管理。使用镜像内的工具，不依赖宿主安装 Fail2ban 或 Python，也避免容器 nftables 与宿主旧版工具之间的集合格式冲突。保护范围是宿主入站端口，包括默认以宿主网络运行的 Nginx；不扩展到其他桥接容器的转发端口。已有其他防火墙限制仍然生效，信任名单不会绕过它们。安装来源可改为兼容镜像地址。

安装时自动准备所需的宿主防火墙内核模块，并配置开机加载；容器无需加载内核模块的权限。手动封禁和解封会检查实际规则结果。更新保留规则和数据，启动失败时尝试恢复原容器；卸载移除本软件的开机加载配置，保留防护配置和数据库，重新安装后继续使用。默认只安装面板和必要的 Nginx，Fail2ban 仍需用户自行点击安装。

## 内置 FRP 服务端

FRP 服务端按需通过官方 Docker 镜像安装，可在独立页面设置连接端口、访问密钥、映射端口范围和网站转发入口。启停、更新、卸载和日志复用统一操作；详见 [FRP 服务端](frps.md)。仅提供 frps，不管理客户端 frpc。

## 导入第三方软件源

在“软件商店 → 第三方商店 → 管理软件源”选择“添加软件源”，输入 JSON 地址或选择本地 JSON 文件。支持 GitHub 文件链接、Raw 链接及其他 HTTP/HTTPS 地址，文件最大 24 KB。远程读取沿用宿主 Agent 的代理设置。

导入只增加列表，不自动安装。卡片统一显示真实状态，点击“安装”打开管理窗口；安装后，有访问入口的软件显示“打开”，所有软件均可通过“软件管理”查看支持的操作及日志。没有声明的操作不显示按钮。

“更新列表”只刷新软件源，修改软件需由用户另外点击“更新”。源不再提供的软件仍显示已安装项，沿用安装时的操作定义进行启停、查看日志或卸载，不显示更新按钮。源内已安装软件全部卸载后可删除该源。

## 第三方接入格式

JSON 只描述软件信息与操作，不包含镜像、端口映射、数据卷、容器名称或容器权限。软件可以使用原生 Compose、systemd、独立程序或其他方式部署；这些配置和安装细节由软件自己的脚本维护，本系统不解析、生成或接管。

```json
{
  "schema": 1,
  "id": "example",
  "name": "示例软件源",
  "applications": [{
    "id": "web",
    "name": "演示网站",
    "description": "演示统一的软件管理操作。",
    "actions": {
      "install": {"command": ["/bin/sh", "-c", "软件提供的非交互安装命令"]},
      "uninstall": {"command": ["/bin/sh", "./manage.sh", "uninstall"], "description": "停止服务，保留用户数据"},
      "status": {"command": ["/bin/sh", "./manage.sh", "status"]},
      "start": {"command": ["/bin/sh", "./manage.sh", "start"]},
      "stop": {"command": ["/bin/sh", "./manage.sh", "stop"]},
      "logs": {"command": ["/bin/sh", "./manage.sh", "logs"]}
    }
  }]
}
```

- `schema` 当前为 `1`；源及应用的 `id` 由小写字母、数字、连字符组成，首字符为字母，最长 40 字符。`name` 是显示名称，`description` 是软件介绍。
- `actions` 必须提供 `install`、`uninstall`、`status`；按软件能力选配 `start`、`stop`、`restart`、`update`、`logs`。状态检查不是用户操作按钮。
- 每个操作的 `command` 为程序及参数数组，直接执行；需要 Shell 语法时明确使用 `/bin/sh -c`。`description` 可说明操作影响，在确认安装、停止、重启、更新或卸载时展示。命令及配置不暴露在普通用户操作页面。
- 可选 `url` 为源的远程更新地址；从远程导入时自动登记实际地址。JSON 不应发布真实凭据。

操作由宿主 Agent 执行，每项软件拥有独立工作目录 `<数据目录>/agent/software/work/<源 ID>/<软件 ID>`，所有命令在该目录运行。软件源具有安装脚本的执行权限，应由管理员导入可信来源。操作权限统一为 `components.manage`、`system.write`；内置 Fail2ban 另需 `security.write`。

提供以下环境变量，供软件自己的脚本定位文件和隔离资源：

| 变量 | 用途 |
| --- | --- |
| `NGINXPANEL_SOFTWARE_DIR` | 当前软件工作目录 |
| `NGINXPANEL_SOFTWARE_ID` | 当前源和软件组合的唯一标识，可用于软件自行命名资源 |
| `NGINXPANEL_SOURCE_ID` | 源标识 |
| `NGINXPANEL_APP_ID` | 软件标识 |

安装脚本自行下载程序、准备依赖及保存自己的配置，并为服务读取的文件设置必要权限；应支持重复执行，失败时返回非零退出码并处理自己的回滚或清理。更新同样由脚本完成，系统不推测其部署方式。卸载后的数据保留方式由卸载脚本定义，应通过操作描述明确说明；系统保留工作目录，不自行删除软件数据或其他服务。

## 状态和入口约定

`status` 必须只查询状态，退出码为 `0` 时在标准输出返回一个 JSON 对象；诊断信息写入标准错误。它可能被实时订阅重复调用，必须快速完成。单次检查最长 2 秒，最多同时检查 4 项软件；超时或格式错误明确显示“状态不可用”，不推断为“已停止”。

```json
{"state":"running","entry":"http://{host}:18080/"}
```

`state` 支持 `running`、`starting`、`stopped`、`unhealthy`、`missing`、`unknown`。可选 `message` 提供可读原因，最多 1024 字符；可选 `entry` 是 HTTP/HTTPS 访问地址，最多 2048 字符，不可包含账号密码。`{host}` 自动替换为当前服务器地址；切换远端服务器后使用目标服务器地址。原生 Compose 软件可由自己的状态脚本查询实际映射端口后返回入口，系统不需要知道 Compose 配置。

| 状态 | 统一展示和操作规则 |
| --- | --- |
| 无安装记录 | 未安装；提供安装和详情 |
| `running` | 运行中；有入口时显示“打开”，管理内提供已声明的停止、重启、更新、日志和卸载 |
| `starting` | 正在启动；管理内提供已声明的停止、重启等操作 |
| `stopped` | 已停止；提供已声明的启动、更新、日志和卸载 |
| `unhealthy` | 运行异常；展示原因及可用操作 |
| `missing` | 需要修复；可更新或卸载后重新安装 |
| `unknown` / 检查失败 | 状态不可用；展示原因和日志入口，不显示未经确认的启停操作 |
| 操作执行中 / 需要处理 | 展示任务状态，阻止重复提交并提供操作日志 |

安装记录、实际运行状态、操作进度分别保留，失败操作不会覆盖实际运行状态。系统内置和第三方软件共用状态标签、卡片主次按钮及软件管理弹窗。“运行管理”提供软件支持的安装、启停、更新、卸载和日志；内置软件的“运行设置”只管理下载来源、开机启动等系统运行选项。“功能入口”跳转对应页面，不在软件管理窗口编辑网站、防护规则或 FRP 连接与映射。FRP 首次安装自动跳转其页面填写连接信息。提交操作后立即打开任务日志。服务日志同样调用软件声明的 `logs` 操作，输出统一进入日志窗口。

内置软件在统一注册表登记状态适配器、操作权限、运行操作及功能入口；网站和防护规则继续由对应功能页提供。第三方接入不需要修改任何前端页面、路由或软件 ID 分支，也不能替换内置适配器。

## 接口接入

复用 `POST /api/v1/components/tasks`，提供幂等请求头 `Idempotency-Key`，请求示例：

```json
{"input":{"action":"software","tag":"","prerelease":false,"plan_id":"","manifest_sha256":"","trust_sha256":"","software":{"action":"start","source_id":"example","app_id":"web"}}}
```

`GET /api/v1/components` 返回软件清单及已安装项的 `state`、`error`、`entry`。前端通过全局唯一 WebSocket 订阅 `software`（`/components`）和 `tasks`，直接接收状态数据；外部启停也由状态检查推送，既不依赖本系统创建任务，也不轮询 HTTP。HTTP 和 WS 共用 `code`、`message`、`data` 格式。

可运行的示例、原生 Compose 文件和独立管理脚本见 [第三方软件 Demo](../examples/software/README.md)。

## 系统更新

进入“设置 → 系统更新”，依次检查更新、下载更新、立即更新。下载时面板保持运行；宿主 Agent 独立完成替换，短暂重启后面板启动并自动执行数据库迁移。Docker 部署拉取发行对应镜像并重新创建面板容器；原生部署切换已准备的程序并重启面板服务。

更新保留数据，失败时查看对应任务日志或宿主服务日志。需要更高管理服务协议的发行通过安装脚本更新。系统更新仍使用安装时配置的发行源及签名校验；第三方软件源不能替换面板程序或内置软件。

卸载本系统或关闭登录防护模块前，请先在软件商店卸载相应软件，避免留下无人管理的防护或容器。内置软件按其既定规则保留数据，第三方软件遵循其卸载脚本声明的行为。
