# 实时状态订阅

浏览器使用 `GET /api/v1/events?topics=tasks,monitoring` 升级为 WebSocket。
`topics` 为逗号分隔的订阅类型；增加或移除类型时重建连接。连接成功后发送一次同步通知，此后仅在订阅状态发生变化时发送通知。断开连接会移除该连接的全部订阅。无订阅者时停止服务端观察任务。

推送沿用 API 返回外壳：

```json
{"code":"OK","message":"状态已更新","data":{"topics":["tasks"]},"request_id":"请求标识","node_id":"服务器永久编号"}
```

通知只标记已变化的资源。前端首次加载、收到通知及重新连接后，通过现有 API 读取所需数据，不使用定时 HTTP 查询。写入仍使用原有 HTTP 接口，不经 WebSocket 执行。现有日志跟随接口继续使用 SSE。

| 类型 | 状态范围 | 所需权限 |
| --- | --- | --- |
| tasks | 后台任务；阶段日志落盘后再次通知 | read |
| monitoring | 最新监控样本及告警状态 | read |
| notifications | 通知健康、事件与投递状态 | read |
| maintenance | 维护状态 | read、system.write |
| backups | 备份文件与备份策略 | read、backup.export |
| firewall | 防火墙运行状态、准备进度及确认结果 | read、security.write |
| listener | 管理入口状态及确认结果 | read、system.write |
| version | 前端资源更新 | read |

远程服务器通过同一地址的 `connection` 参数指定已登记的连接编号。控制端使用现有证书固定校验、目标身份和权限约束建立单跳 WSS 转发，不向浏览器暴露密钥。备份、防火墙执行和管理入口仍只支持直接管理本机。

Cookie 登录要求严格同源握手。连接期间重新核对会话、授权及远程连接状态。每个服务最多 32 条实时连接；服务端每 15 秒发送 Ping，45 秒内无响应则关闭连接。前端按服务器共用连接，断线后逐步延迟重连，重新连接后同步状态；页面销毁、退出登录及切换服务器会清理相应订阅与重连定时器。

服务端以一个共用观察任务比较已订阅状态，每 2 秒检查一次，不创建每个浏览器独立的状态查询循环。推送不携带配置、凭据或日志正文，数据读取仍由各业务 API 校验权限。
